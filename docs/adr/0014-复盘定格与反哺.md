# ADR-0014：C4 复盘定格与反哺——阈值史、as-of 判据、提案不写账本

**状态**：已接受（2026-10-29，七项拍板全按推荐）；配套 `.scratch/phase3-review/spec.md` v1.0。
**上游**：`docs/design/business-architecture.md:147-150`（R-28/29/30）、`:184`（复盘聚合）、`:194`（F3）、`:200-207`（不变量）、`:242`（拍板 4）；`docs/design/system-architecture.md:23`（advisor C3/C4）、`:61`（复盘聚合）、`:76`（F3 到期复盘）、`:88`（隔离区）、`:98`（审计链）、`:181`（拍板 6）；`docs/design/metric-system.md:91-110`、`:166-178`；前置 ADR-0010/0012/0013 与三期-1/2/3 实现。

## 1. 背景与问题

1. **C4 是三期唯一没有承载物的子域**：目标（C1）、双阈值（C2）、建议（C3）都已落地，但「到期复盘→归因→反哺」仍只有文字（`business-architecture.md:147-150`；`system-architecture.md:61`）。
2. **`band_basis="as-of"` 至今不可兑现**：ADR-0012 D8 明确本期只给 `current`，阈值史「延三期-4」（`docs/adr/0012-C2双阈值与B4域级汇总.md:37-39`；`.scratch/phase3-c2/spec.md:287-296`）。C4 是唯一消费方，必须在此决定「历史判据从哪来」。
3. **目标版本已经不可变**（`models.py:286-335`；ADR-0010 §3.3），因此 C1 的 as-of 判据可精确解析；**C2 的阈值仍就地可变**（`models.py:76-89`、`allocation_service.py:140-179`），只靠 `audit_log` 留痕，无法按 as-of 查询。
4. **「复盘」与「建议」是两种对象**：建议有 LLM、10 项门、30 天过期与生成状态机（`models.py:379-413`；ADR-0013 D5/D6）；复盘是确定性的、人主导的、无过期。把复盘塞进建议状态机会让确定性结论被门误杀。
5. **复盘必须结构性不可写账本**：业务架构不变量 4/6（`:203`、`:205`）与 C3 的三重隔离（ADR-0013 D3 `:32-38`）已经把「机器产出不落账」变成测试；C4 不能开后门。

## 2. 决策

**D1 范围：定格＋归因＋结构化提案；不做自动执行/自动改目标/自动改阈值。**
复盘只产出「人的决定」与「结构化提案」；任何目标/阈值生效都走既有 C1/C2 写端点（独立事务、独立审计）。依据：不变量 6、R-30、ADR-0010 §3.3「采纳=人调用本端点」（`:109`）。

**D2 复盘对象＝as-of 目标版本＋as-of 阈值带＋选定已采纳建议批次。**
两个观察锚点（start/end），各自解析「当时生效」的目标版本与阈值 revision；配置行同时冻结 start/end `actual_percent`，作为「有没有真执行」的账本侧证据，不引外部基准、不读流水。依据：R-28、拍板 4、C3 预埋（`.scratch/phase3-advisor/spec.md:157`）。

**D3 定格时点＝复盘创建时；`as_of` 是观察终点，不是创建日。**
快照 write-once＋`snapshot_sha256`；之后改目标/阈值不改写旧复盘；读取重算 hash，不一致 409。依据：`metric-system.md:106`；`info_set.py:283-309` 同模式。

**D4 阈值史＝`allocation_target_revisions`（0020），append-only，写侧单点追加。**
revision 携带与当前表同名列，`band_service.resolve_band(revision)` 零改动复用。**不建触发器自动抓**：拿不到 actor/reason，且单测底座只 `create_all`（`tests/conftest.py:12-20`），会制造「测试史表空」的假绿；与本金/归属「变更史权威」同纪律。回填 `effective_date = DATE(updated_at)`，**不伪造更早历史**。

**D5 无史＝无判据，不回退当期尺。**
`as_of` 早于首条 revision → `band=null`、`grade=null`＋`REVIEW_BAND_HISTORY_MISSING`。理由：四态纪律允许「不可判」，但**错尺比无尺更坏**（`metric-system.md:93`、`:106`）。`band_basis` 仍为 `as-of`（解析器已按 as-of 执行，只是没有史）。

**D6 快照载体＝`advisor_reviews.snapshot_json`＋sha256，不做行式条目。**
C3 信息集行式是为了让门逐条校验引用（ADR-0013 D4）；复盘没有机器门，快照是整体展示文档，JSON＋hash 足够；不为此建键空间与第二套 builder。若未来要跨复盘查询，再加投影表。

**D7 反哺提案＝独立 `advisor_review_proposals`（advisor 隔离区内）。**
`kind ∈ {goal_version, threshold, allocation_target, narrative}`，`payload_json` 结构化；校验直接复用 `goal_service`/`band_service` 既有函数，不发明第二套。表名沿用 `advisor_` 前缀（ORM `AdvisorReview*`），API 仍叫 `reviews`。不复用 `advisor_suggestions`：无结构化新值、过期/门/LLM 语义冲突。

**D8 采纳边界＝只记决定，不写目标/阈值/账本。**
`adopt` 仅更新提案状态＋审计；`applied_kind/applied_ref` 为可选人工关联且不校验数值（允许「同意方向、数值调整」）。系统永不自动生效。依据：不变量 6；ADR-0010 §3.3；C3「采纳≠落账」（ADR-0013 D1 `:18`）。

**D9 归因＝四分类枚举＋人工；系统只陈列证据。**
`market_moved | advice_wrong | not_executed | execution_drift`；不设第五类；允许空归因但关闭需结论文字；不做自动归因、不做 LLM 叙述。依据：R-29；`system-architecture.md:76`。

**D10 代码归属＝`services/advisor/`，继承 C3 的隔离测试。**
复盘只依赖扩展后的 `ReadModel`（新增 `goal_version_as_of` / `allocation_rows_as_of` 两个只读方法）与 `band_service` 纯函数；AST 测试扩到 `services/advisor/review*.py`、`routers/reviews.py`；行为测试断言提案采纳前后账本五表与 `goals/goal_versions/allocation_targets` 零变化。

**D11 状态面不扩 as-of。**
`/api/metrics/status` 仍恒 `current`；as-of 只在复盘快照内。日常看板与历史定格是两种用途，混成一个契约会重演 C2 已避免的「历史请求静默换尺」。依据：`metric-system.md:106`；ADR-0012 D8。

**D12 迁移 0020/0021，无 CLAIM、无 down。**
0020 阈值史（表＋索引＋append-only 写保护触发器；**不**在 `allocation_targets` 上建自动抓取触发器）；0021 复盘三表＋写保护触发器。回滚＝revert 代码；表/触发器残留无害。依据：`system-architecture.md:91`；`db_migration_service.py:7-15`。

## 3. Considered Options（为什么不是别的）

| 议题 | 弃选 | 理由 |
|---|---|---|
| 阈值史 | 零阈值史迁移「快照即史」 | `band_basis=as-of` 只在创建时点成立；观察终点后改阈值会让「当时的尺」失真；C2 已把史表时点定在 C4 |
| 阈值史 | 从 `audit_log` 回放 | 审计是证据不是查询维度；直连 SQL 本就不入审计；回放成本与专表相当，语义更脆 |
| 阈值史 | 触发器自动抓 | 无 actor/reason；测试底座不跑迁移 → 假绿 |
| 快照 | 行式条目（仿信息集） | 无机器门逐条校验需求；键空间与 builder 是白付的复杂度 |
| 快照 | 读时重算（不落快照） | 阈值/目标会变，复盘必须回答「当时怎么看」，不能每次重算 |
| 提案存储 | 复用 `advisor_suggestions` | 门/过期/LLM 语义错配；建议项无结构化新值（`models.py:416-436`） |
| 提案生效 | 采纳即调用 C1/C2 写端口 | 第二条写路径，绕过既有校验/幂等；违反「采纳=人调用本端点」；目标由人设定被稀释 |
| 归因 | 规则/LLM 自动归类 | 归因是价值判断；自动归类会把「建议错了」变成系统自辩 |
| 归因 | 增加「无法归因」第五类 | 违反 R-29 四分类；用「空归因＋结论」表达不确定更诚实 |
| 状态面 | `/metrics/status?basis=as-of` | 混合看板与复盘；C2 已明确不提供 |
| 代码归属 | `services/planning/` | 需重建隔离测试；advisor 已承载 C4（`system-architecture.md:23`） |

## 4. Consequences

**正面**

- 三期闭环：目标→偏离→建议→采纳→复盘→反哺，每步有人裁决与审计；R-28/29/30 有承载。
- `band_basis=as-of` 首次可兑现：C1 靠不可变版本，C2 靠 append-only revision；旧复盘永久可解释。
- 反哺不产生第二条写路径：目标/阈值仍只由 C1/C2 端点写，校验/幂等/审计不重复。
- 隔离可验证：AST＋行为＋触发器三层，和 C3 同一套证据形态。

**负面/代价**

- 两次迁移＋回填；0020 之前的 as-of 判据不可得（显式 `grade=null`）。
- 复盘创建即冻结，若起点选错只能新建复盘（不可编辑/删除）——以「证据不可改」换「可纠正性」。
- 采纳与生效分两步，闭环完成度依赖人的纪律；「已采纳未关联」可能长期存在。
- 同日阈值多次变更只有日粒度，as-of 精度到「日」。
- 信号快照是「当期规则重算」，不是历史信号；已在快照标注，但仍可能被误读。
- 配置实际占比按「锚点快照 + 当前属性树」重算；属性分类变更史未版本化，快照标 `classification_basis=current_tree`，不声称还原当时分类。

**后续（不在本 ADR）**

- `alert_rules` 版本化与历史信号重放；季度自动发起/通知；LLM 复盘叙述；未采纳建议反事实；成员级复盘（四期）。
- 可选统一：新激活 GoalVersion 的 `criterion_json` 写 `schema=2` 完整 C1 带（本期不做）。

## 5. 拍板结果（2026-10-29，七项全部按推荐）

1. 阈值史：**加 0020**（`allocation_target_revisions`）／不做零迁移「快照即史」。
2. 观察起点默认顺序：建议最早信息集 → 上次复盘 → 目标版本生效日。
3. 采纳边界：**只记决定**；不采纳即写。
4. 采纳后跳转：**不预填**；不做深链预填。
5. 关闭门槛：**结论必填、归因可空**。
6. 复盘**不强制**关联建议；纯目标复盘合法。
7. 代码归属：**`services/advisor/`**；不新建 planning 写面。
