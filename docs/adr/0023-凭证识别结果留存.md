# ADR-0023：凭证行留存识别快照（`recognition_json`），供日后识别率检查

**状态**：**已接受（2026-11-05，业主签字，随 `.scratch/evidence-naming/spec.md` L2 冻结）**
**上游**：业主 2026-11-05「ocr或ai识别的内容最好存储下来」→「可以作为后期识别率检查的依据」；`.scratch/evidence-manager/spec.md`（凭证管理的既有边界）
**下游**：迁移 `backend/migrations/0032_add_evidence_image_meta_and_recognition.py`；`backend/services/screenshot_service.py`（`PARSER_VERSION` 常量与序列化）；`backend/services/evidence_service.py`（统一写入函数）；`backend/routers/screenshots.py`（`/preview`、`/preview-jobs`、`/apply` 三个写入点）；`frontend/src/app/screenshot/page.tsx`（AI 路径回传 `recognition`）
**性质**：**新增可空列（可回退）**，但「识别结果是否值得长期留存」是一次性取向决策，故记录。

---

## 1. 决策

1. **在 `screenshot_evidence` 上新增可空列 `recognition_json`（TEXT / JSON）**，保存一次识别行为的完整快照，与凭证行共存亡（删凭证即删快照，不设独立保留期）。
2. **快照分两段**：`recognized`（机器当时给出的：`engine`、`source`、`parser_version`、`parsed_at`、`items`、`total`、`date_text`、可选 `blocks`）与 `adopted`（人改后真正落账本的行、`corrected_rows`）。识别率 = 两段之差；只有 `recognized` 而无 `adopted` 就只能看「机器给了什么」，看不出「人改了多少」。
3. **存 OCR 原始块（文本 + 坐标）**：换规则后可离线用新规则重解析同一张图，不必重跑 OCR（单张约 4 分钟）。这是 `ParsedScreenshot.raw_blocks` 首次被序列化。
4. **体积上限 1 MiB**：超限先丢 `blocks` 并置 `blocks_dropped: true`，仍超限只留条数与摘要。**存证永远优先于存全**——不能因为快照太大而让上传失败。
5. **新增 `PARSER_VERSION` 常量**，凡词表/规则/算法变更手工递增。没有它，「这次识别率变差」无法归因是规则改了还是图换了。
6. **AI 路径由前端回传**：`engine=ai` 时服务端不调模型，识别行在前端产生。`/preview` 与 `/apply` 增加**可选**表单字段 `recognition`（additive，缺省行为与今天一致）；传了就落库，没传记 `items: null` + `note`。不接受「AI 识别结果查不到」这种半覆盖——要么存得下来，要么明确标出这条没存。
7. **三个写入点共用一个服务层函数**，路由里不得各写一遍序列化逻辑。

## 2. 否决的方案

| 方案 | 否决理由 |
|---|---|
| 只存解析后的行，不存 `blocks` | 省一个数量级的体积，但换规则后必须重跑 OCR（4 分钟/张），「规则改版前后对比」当场不可行——而这正是存它的主要理由。 |
| 存全量 OCR 原文到独立文件（`data/evidence/**/*.ocr.json`） | 多一套磁盘生命周期要管（删除、备份、孤儿），而行内 JSON 天然随行删除。当前体量与上限都撑得住。 |
| 只在采纳时存（不存预览时） | 大量凭证的识别过程发生在预览阶段，放弃这一半就丢掉「识别给了什么但人没采纳」的最有价值样本。 |
| 记进 `preview_jobs` 并延长保留期 | `preview_jobs` 是短期任务缓存（当前 0 行、跑完即弃、以 job 而非凭证为主键），既对不上凭证生命周期，也答不了「这条凭证当时的识别是什么」。 |
| AI 路径不存（服务端拿不到） | 业主明确要求 AI 也作为识别率依据；缺口靠「前端回传」补，成本只是一个可选字段。 |

## 3. 代价

- 每张凭证多出几十 KB 到 ~1 MiB（OCR 块）；28 条存量回填为空（历史无从追溯，不伪造）。
- 新增一个手工维护的 `PARSER_VERSION` 纪律：忘记递增会让归因失真。
- 前端 `/apply` 与 `/preview` 需在 AI 路径多传一个字段（前端契约变更面）。
- 识别快照里含截图中的真实金额与名称文本——与凭证原图同处本地库，不产生新的对外暴露面（不入 git、不进日志）。
