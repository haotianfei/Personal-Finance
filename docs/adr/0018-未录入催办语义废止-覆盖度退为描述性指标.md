# ADR-0018：未录入催办语义废止——覆盖度退为描述性指标

**状态**：已接受（2026-10-31，业主拍板）；同日生效。
**同日修订（2026-11-10）**：**D5 已被 [ADR-0031](0031-资产记录元数据落项级与分期编辑入口退役.md) 取代**——「批量按账期添加」与「复制上期」两个入口连同端点、service、测试、审计契约一并删除；**D5 原文保留，不改写**。
**上游**：ADR-0009（部分录入期沿用值与覆盖度）、ADR-0015（零额快照合法化）、ADR-0016（当前值可就地修改但仍为追加）、`CONTEXT.md`「覆盖度」「部分录入」「账期」词条。
**下游**：`frontend/src/components/dashboard/EntryStatusBanner.tsx`（删除）、`GET /api/management/entry-status`、`POST /accounts/{id}/zero-fill`、`GET /accounts/{id}/fill-preview`（删除）、`backend/services/account_reminder_service.py` 补录机器（删除）、`analysis_service._coverage_for`（保留，仅内部）。

## 1. 背景与问题

首页黄条「数据日期 2026-10-31 · 还有 16 个账户未录入」是**账期思维**的遗留：它假定每一期都必须把每个账户补齐，欠一条记录就是待办。当前值模型建立后，这个前提不再成立，而横幅自身又制造了三重问题：

1. **参考日被录入行为反向定义**：判定取 `reference_date = MAX(assets.asset_date)`（全库最新数据日期，`account_reminder_service.py:24-26,55`），`missing = 该账户在参考日没有任一条资产行`（`:93`）。于是「今天只录了一个账户」＝参考日跳到今天＝**其余所有账户立刻变成未录入**。一次合法的小步更新，制造一次全网假警报；警报常驻，久了即背景噪音。
2. **粒度错位**：当前值就地编辑的最小单位是**资产项**（`GET /api/assets/current`，ADR-0016 D1）；横幅却按**账户**汇总，账户里录了 1/N 个资产项也算「已录」。信号既误报又漏报。
3. **动作预设了一个不该存在的欠账**：一键置0、复制上期金额、批量按账期，全部以「欠本期一条记录，先填上」为前提。但在当前值模型里：缺失是合法状态（ADR-0015 D4、ADR-0016 D3），「无变化」应表现为不写而不是复制出一条新快照，「清零」是测量值而不是占位符（ADR-0015 D1）。

同时，**新鲜度已经有一等公民**：`/api/assets/current` 的读模型本就逐资产项返回 `freshness: fresh | stale | missing`（阈值 30 天，`asset_service.py:854`），记录页「当前值」视图已用徽标 + 记录日期呈现（`CurrentValueTable.tsx:44-46,718,754-755`）。横幅是在这套机制之外另建的第二条通道。

## 2. 决策

**D1 催办语义废止**：删除首页「数据日期 X · 还有 N 个账户未录入」横幅及其专属 HTTP 面 `GET /api/management/entry-status`。不再存在「以某期为单位的录入催办」这一概念。

**D2 补录工具一并退役**：`POST /accounts/{id}/zero-fill`、`GET /accounts/{id}/fill-preview` 与 `account_reminder_service` 的 `preview_fill_account` / `fill_account` / `zero_fill_account` / `_fill_plan` 全部删除。不为「补齐一期」保留任何批量造记录的入口。

**D3 不新增替身横幅**：新鲜度由记录页「当前值」视图承担（`fresh/stale/missing` + 记录日期 + 参考日选择器）。首页不再有第二条新鲜度通道——重复口径必然漂移，这已是本仓库的既有教训（改名双计、口径复制两份）。

**D4 覆盖度保留但降级为描述性指标**：`get_entry_status` 与 `analysis_service._coverage_for` 保留，作为**纯派生、无 HTTP 面**的内部函数，继续为 summary、趋势点部分录入标记、`data_coverage` 指标、目标达成度、顾问 `DATA_PARTIAL` 闸门供数。其语义固定为「历史某一期数据有多密」的描述，**不再驱动任何催办或提醒**。

**D5 分期编辑能力不删**：记录页的「批量按账期添加」（`POST /assets/batch-create-by-period`）与「复制上一条」（`CopyFromLastPanel`）是用户主动的编辑能力，与催办无关，保留原样。

## 3. 后果

- **能力净损失（明示承认）**：账户级「从未录入」总览消失。资产项维度的 `missing` 只覆盖「**已有**资产项但无记录」的情形，**一个资产项都没有的账户不会出现在任何视图里**。若将来需要，正确姿势是在「设置 · 账户」列表上加「无资产项 / N 项缺记录」标记，而不是恢复首页催办。
- `remind_enabled` 开关保留（覆盖度分母仍读它），但其含义由「要不要提醒我」退为「是否计入覆盖度分母」；若需改名，走词条修订。
- 覆盖度的 5 个消费方零变化（summary / 趋势 / `data_coverage` / goal / advisor），历史图表数值不变，无 schema、无迁移、无数据回填。
- 账期（日/周/月/季/年）作为**分析时段分组**继续合法存在；本 ADR 只废止「以账期为单位催办录入」。
- 回滚成本低：恢复组件与端点、`git revert` 即可，无数据面影响。

## 4. Considered Options

- **改造而非删除**（参考日改今天、粒度改资产项、警告降级为中性）→ 弃：改造后仍是一条与「当前值」视图重复的新鲜度通道，两套口径必然漂移；且「催办」这个动作在修正思维下本无对象。
- **只删前端、留 API** → 弃：留下无消费者的写路径（能一键把整组资产造 0）比留 UI 更危险。
- **连覆盖度一起删** → 弃：覆盖度是历史数据密度的描述性事实，分析页与「含沿用值」注记仍需要它；它与催办并无必然耦合，耦合只是实现上复用了同一个函数。
- **保留横幅但默认折叠** → 弃：噪音的解法不是藏起来，而是不再产生。
