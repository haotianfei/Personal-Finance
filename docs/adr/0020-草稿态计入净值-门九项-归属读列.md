## 1. D1 草稿态项**计入**净值，并强制披露未补齐规模

**决策**：`asset_items.status='draft'`（分类四维未补齐）的资产项，**照常计入 as-of 合计**。as-of 聚合的排除谓词只排除归档项（`status='archived'`，ADR-0017），不排除 `draft`。同时，凡是输出合计的口径出口必须附带未补齐规模披露：`summary.unclassified_count`、`unclassified_asset_amount`、`unclassified_liability_amount`（按 side 拆毛额 + 计数）。

**现状证据**：`backend/services/analysis_service.py:210-216`（`_unclassified_as_of` 注释即本决策原文：「draft 项照常计入净值——钱是真实存在的」）；`backend/tests/test_draft_disclosure.py:1-10`（三条断言钉死：合计含 draft、披露按 side 拆、归档项既不进合计也不进披露）。

**理由**：`draft` 只由「先建项、后补分类」的路径产生——截图采纳、CSV 导入、`0008_asset_items` 迁移对存量项的回填（`backend/migrations/0008_asset_items.py:124-127`）。这三条路径产生的项，钱**已经真实发生**。若排除，净值会系统性少算，且**没有任何告警会提示缺口**——少算比多算危险得多，因为它不可观测。

**与 ADR-0019 的冲突（显式记录）**：ADR-0019 **D9** 原文「草稿项不进任何汇总」，§3 进一步要求「所有聚合谓词、导出、提醒都要加 `status <> 'draft'`；漏一处就会把草稿算进净值」，`docs/design/资产分类规范.md:171` 复述同句。本 ADR D1 **取代**该表述，且方向相反。ADR-0019 保留原文不动，仅在状态行加修订指向本 ADR。

**否决的替代方案**：
1. **不进汇总**（ADR-0019 原方案）。否决：净值少算且不可观测；用户看到的是一个偏小的数字，没有任何界面元素能提示它偏小。
2. **完全等同 active、不披露**。否决：业主无法知道合计里有多少来自未分类项，也就无法判断分类工作的实际缺口。
3. **draft 项记 0 金额**。否决：伪造历史行，违反 ADR-0007 append-only 与「不改写历史资产行」（ADR-0019 D10）。

**代价（如实记录）**：D1 把正确性从「结构保证」降为「口径一致」，因为合计的数值依赖实现，而不是依赖 schema。ADR-0019 §3 加谓词是**安全默认**（漏了只是少算）；D1 是**危险默认**（口径漂移就是静默错账）。

**缓解方案的演化（初版设想已被否决）**：初版设想是「给每个输出合计的出口都加 `unclassified_*` 三个字段」。只读侦察列出**20 个合计出口**（`/analysis/summary`、总趋势、期间对比、混合图、按项/按类/按流动性的各维度趋势、增值、归因、占比两个端点、指标状态、目标进度、复盘、顾问信息集、配置分析、预警差额），且**目前只有 `/analysis/summary` 一处带披露**。给 18 处复制三个字段的后果是：字段会漂移、每个出口要各自算一遍未补齐规模、前端要各自渲染。**否决**。

替代方案是**单点披露 + 同源不变量**（D4）：披露只在 `get_summary` 产出一次，其他出口的义务不是"复制字段"而是"数值必须与它相等"。这比字段复制更强——复制只能保证字段存在，相等才能保证口径同源。

## 2. D2 确定性门由 10 项改为 9 项（8 blocking + 1 warning）

**决策**：`GATE_DATA_PARTIAL`（覆盖度闸门）退役。确定性门契约固定为 **9 项**：blocking 8 项不变，warning 只剩 `GATE_THRESHOLD_SOURCE`。

**现状证据**：`backend/services/advisor/gate.py:1`（「9 项纯函数检查（8 blocking + 1 warning）」）、`:9-12`（原第 10 项的退役说明）、`:36`（`WARNING = (GATE_THRESHOLD_SOURCE,)`）。

**理由**：该项检查的输入是 info_set 的 `coverage.ratio` / `coverage.partial`。ADR-0018 已把覆盖度退为描述性指标，`data_coverage` 指标随后下线，info_set 不再产出这两个字段——检查对**任何真实输入**都失去可判定对象，只剩恒真或恒不可判定两种可能。一个恒真的检查项在门里是**假保证**，比没有这一项更糟：它会让「9 项全过」看起来比实际的保证更强。

**与 ADR-0013 的冲突（显式记录）**：ADR-0013 **D6** 原文「确定性门＝10 项纯函数检查（8 blocking + 2 warning）」，并逐个列名。本 ADR D2 将项数改为 9。ADR-0013 保留原文，仅状态行加修订指向本 ADR。

**附带义务**：`.scratch/phase3-advisor/spec.md:410` 仍列第 10 项。该 spec 状态为已冻结 v1.0，须做一次**同窗口修订**（删该条 + 提版本），不得留「spec 说 10、代码做 9」的长期分裂。

**否决的替代方案**：
1. **保留空检查**（为兼容而兼容）。否决：恒真检查污染门报告，且掩盖「这一维已经不存在了」这一事实。
2. **连 `GATE_THRESHOLD_SOURCE` 一起去掉，门缩到 8 项**。否决：该 warning 仍有真实输入（阈值无来源），不在本次退化范围内；能报的问题必须继续报。

## 3. D3 归属唯一真相源改为 `asset_items.owner_id` 列

**决策**：资产项当前归属以 `asset_items.owner_id`（值域 `members.id`）为**唯一读写入口**；`asset_item_owner_changes` 保留为 append-only **纯审计流水**，不再作为当前值的读源。写路径必须在**同一事务**内「写列 + 追加史行」。`family_pool` 归属请求返回 422。

**现状证据**：`backend/services/asset_owner_service.py:3-8`（「唯一真相源：`asset_items.owner_id`（值域 `members.id`）」及迁移理由）、`:46-52`（`FAMILY_POOL` 退役，仅作报错指路）、`:220-221`。

**与 ADR-0011 的冲突（显式记录）**：ADR-0011 决策 1 原文「追加 append-only 变更史……当前值=最新行，无行=未标注；**不设 `asset_items.owner_id` 当前列（单真源）**」。该「不设列」条款由本 ADR D3 取代。ADR-0011 其余决策（append-only 触发器、家庭池语义、写路径收口、读路径 item 优先）不变。

**理由**：ADR-0011 时代的读源是「变更史最新一行（`effective_date DESC, created_at DESC, id DESC`）」，其单真源假设成立。但 ADR-0019 把分类移到资产项级后，列表/记录/导出/筛选统一读 `asset_items` 上的列；此时「当前归属在史里、其余属性在列里」导致分裂——**改了归属，列表与导出看不到**（`asset_owner_service.py:5-7` 原文即此现象）。分裂的根因不是少写一次，而是「同一件事有两个可读位置」。

**代价**：列与史之间存在一致性窗口。史的价值从「真相源」降为「可审计性」——若某次写完列但漏写史，史不再能证明列的来历，且**触发器无法跨表保证同事务**。缓解：写入口唯一（`asset_owner_service`），其他路径禁止直写该列。

**否决的替代方案**：
1. **维持变更史为读源**（ADR-0011 原样）。否决：列表/导出与记录页显示不一致，属用户可见的分裂，且无性能优势。
2. **列 + 史双写但史仍为读源**。否决：双真源必然漂移，且读路径要多一次「最新一行」子查询。
3. **删掉变更史**。否决：ADR-0011 的审计诉求（归属何时由谁改、为什么）独立成立，且 ADR-0007 的 append-only 原则要求留痕。

## 4. D4 总额同源不变量——所有自称「总额」的出口必须与 `get_summary` 相等

**决策**：`analysis_service.get_summary` 的 `total_assets` / `total_liabilities` / `net_worth` 是**唯一权威总额**。任何向用户或下游模型自称「总额/净值/总资产」的出口，其数值必须与之**精确相等**（`Decimal` 相等，不是近似）。未补齐规模披露**只在这一处产出**，其他出口不复制字段，但必须同源。

**为什么必须是"相等"而不是"相近"**：只读侦察发现三处现有出口与权威值不同源，且都是**独立实现的求和**，不是复用：

| 出口 | 现状问题 | 后果 |
|---|---|---|
| `attribution_service._net_at`（归因页期初/期末净值） | 复用 `appreciation_service._active_rows`，该函数只过滤 `superseded`，**不过滤归档项** | 归因页期末净值**含已归档资产**，违反 ADR-0017；其 docstring 却声称"与 summary/proportion/allocation 同口径" |
| `allocation_service.get_total_assets`（配置分析分母） | 仅 `asset_date == d` + `side='asset'`，**无** `superseded_by IS NULL`、**无**归档过滤 | 同日存在被取代行时**重复计数**，且含已归档项 |
| `export_service.generate_csv`（导出） | 显式 `AssetItem.status != 'draft'`，注释写「D9：草稿不进任何对外口径」 | 导出 CSV **缺草稿项**，与首页合计对不上账 |

三处的共同根因不是"算错了"，是**各自重算了一遍**。所以本决策的约束对象是"是否存在第二套求和实现"，不是"某个函数写漏了一个 where"。

**验收方式**：`backend/tests/test_total_consistency.py` 维护一张 `DECLARED_TOTAL_EXPORTS` 清单（出口名 → 调用方式），逐个断言与 `get_summary` 相等；**新增任何总额出口必须登记进该清单**。这是本 ADR 唯一可自动化的部分。

**代价**：登记制依赖人工。新增出口若既不登记也不复用 `get_summary`，测试不会失败（测试只遍历清单内的东西）。缓解：清单文件头写明"新增总额出口必须登记"，并在 code review 时对照 `routers/` 是否新增了求和端点。这条弱点比 D1 初版的弱点小一个数量级（一个文件 vs 20 个出口），但**不是零**。

**否决的替代方案**：
1. **给 20 个出口各加披露字段**（见 D1）。否决：字段漂移 + 20 份重复计算。
2. **只让 summary 存在、删掉其他出口的合计字段**。否决：趋势/占比/归因的总额是各自页面的必要输入，不能都改调 summary（多一次查询且耦合）。
3. **抽一个 `total_service` 供所有出口调用**。方向正确，但属重构；本次以"修 3 处 + 立对账测试"为限，重构登记为后续候选。若未来再出现第 4 处漂移，应直接做这次重构。

## 5. 影响面与可回退性

| 决策 | 波及 | 可回退性 |
|---|---|---|
| D1 | 所有 as-of 合计出口的披露字段、汇总页、导出 | **不可静默回退**：改为排除 draft 会导致历史净值口径突变，须新 ADR + 数据重算 |
| D2 | 顾问门契约（`gate_version`）、spec §2.4/§5.2/§5.4 | 可回退（恢复检查项即可），但需 info_set 重新产出 coverage 字段 |
| D3 | 归属读路径、变更史语义、前端筛选/导出 | 可回退到读史（保留列），代价是恢复到已知分裂状态 |
| D4 | 三处求和实现的数值（归因/配置分母/导出）、对账测试清单 | **不可回退**：回退即恢复"三个数字对不上"的状态 |

三项均**不回退**为本次建议结论；回退方案记录在此仅供未来评估。
