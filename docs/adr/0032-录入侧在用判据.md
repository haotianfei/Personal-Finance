# ADR-0032：录入侧的「在用」判据（归档项不进匹配、不进未识别项、不可写入）

**状态**：**已生效**（2026-11-10 代理起草；同日业主在对话中裁决两条口径并指示「冻结，接着开票实现」，随上游 spec 同日冻结。签字记录：业主指令原文留档于 `.scratch/archived-ingest-scope/spec.md` 头部）
**上游**：业主 2026-11-10 报告「复核页未识别项列出的项，在关联选择器里搜不到」；`.scratch/archived-ingest-scope/evidence/2026-11-10_archived-scope-impact.md`（只读影响面）
**下游**：`backend/services/screenshot_service.py`（`_group_latest_rows` / `compute_preview` / `_upsert_asset` / `apply_supplements` / `_supplement_item_classification`）；`frontend/src/app/screenshot/page.tsx`；预计无迁移。**不涉及** `lineage_links` 的增删（见 §4）
**性质**：**可回退**。改动是读法与校验，无表结构变更、无历史数据改写；回退即恢复旧的读法（会重新出现「归档项进未识别项」与「金额写进归档项」两条缺陷）

---

## 1. 问题

「哪些资产项算系统现有」在两个方向上各有实现，且互不一致：

1. **读侧全裸**：截图录入的现有项读法（`_group_latest_rows`，`screenshot_service.py:1660-1677`）只按 `assets.asset_name` 前缀取组内最新快照，不看 `asset_items.status`。归档项的陈年快照因此被当成「在用」，进入「未识别项」（keep/zero 行）与匹配候选（`known_names`）。
2. **身份侧与 bind 侧已收口**：身份提示（`_active_items`，`:519` 过滤 `!= archived`）与 bind/merge 决策（`:2257`、`:2274` 409）都拒绝归档项。
3. **后果不是文案不一致，是算错钱**：归档名在匹配候选里 → OCR 命中即生成 update 行 → `_upsert_asset`（`:2147-2150`）把金额写进归档项；而 as-of 聚合自 `archived_effective_from` 当日起剔除该项（`analysis_service.py:65-80`、`:234`）→ 用户看到「已录入」，总额里却没有这笔钱。
4. **前端多加了一层私设**：关联选择器 `.filter(status === 'active')`（`page.tsx:1152`）比后端契约（只拒 archived）更严，连带漏掉 `draft` 项（`draft` 是计入净值的在册状态，ADR-0019/0020）。

## 2. 决策

**D1（增量，替换 0026 D4 的适用范围）**：录入侧统一「在用」判据 = `status != 'archived'`（`active` 与 `draft` 都算在用）。落点：现有项读法、匹配候选、未识别项生成、前端选择器。`_identity_candidates` 现已是此判据，不动。

**D2**：归档项不得作为任何写入目标。`_upsert_asset` 解析到 archived 项时回 `ITEM_ARCHIVED` 行级错误，不得静默写金额或写 0；`_supplement_item_classification` 的 ITEM_ARCHIVED 不再被静默吞掉。

**D3**：OCR 命中已归档名时，不生成 update 行，生成 create 行，并在该行标注血缘去向「历史上已并入 <目标项名>」（数据取血缘 family）。用户的判断依据保留，钱的落点交由用户显式选择。

**D4**：可见性优先于静默过滤。关联选择器对搜索命中的归档项显示一行不可选说明（归档生效日 + 并入目标），而不是什么都不显示——本次事故的直接观感就是「面板说有、选择器说没有」。

**D5**：口径变更必须披露。`existing_items` 与 `total_current_system` 不再含归档项，属用户可感知的对账基线变化，须在 CHANGELOG 与 `CONTEXT.md` 记明。

## 3. 否决了什么

- **把归档项加进选择器并允许 bind**：与 R-37/ADR-0026 D4 冲突；更要命的是金额会写进归档项而聚合剔除它，「已录入但总额不变」比现状更难诊断。否决。
- **只在 `compute_preview` 过滤**：`apply` 接受客户端回传的行，补录端点（`resolve_supplements`）也不经预览，仍可把归档名送进写路径。否决（故增设 D2 兜底）。
- **静默忽略命中归档名的行**：用户会以为这笔已录入。否决（改 D3 的 create + 提示）。
- **把「归档项恢复独立计入」并进本 ADR**：那要求撤销 `merge` 链，与「链不可变（`lineage_service.py:12` 拍板 8，`0014_lineage_links.py:35-47` 触发器）」正面冲突且不可回退，属另一项决策。否决（见 §4）。

## 4. 遗留与边界

- **不解除任何项的归档、不增删 `lineage_links`**。恢复独立计入的两条候选（保链只翻 status / 破触发器删链）与代价见 evidence 文件 §2，需独立裁决与独立 ADR。
- **不动聚合与报表**：as-of、总额、趋势、占比、预警、归因一行不改。
- **不修 `get_returns` 不过滤归档的既有偏差**（`analysis_service.py:987-998`），另立票。
- 对 ADR-0026 的**建议修订行**（待本 ADR 生效时由业主决定是否加入 0026 正文，不改原结论）：
  > **修订（待 ADR-0032 生效）**：D4「bind 目标须 active」的适用范围由录入侧全部读法与写路径继承，判据统一为 `status != 'archived'`（`draft` 亦可用于 bind 与匹配）；归档项一律不进匹配候选、不进未识别项、不可写入。
