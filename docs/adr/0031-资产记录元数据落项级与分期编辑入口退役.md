## 1. 背景

本期解决两件事，它们共享同一个判断：**什么该挂在「资产项」，什么该挂在「记录行」**。

ADR-0018 D5 当时写道：「分期编辑能力不删：记录页的『批量按账期添加』（`POST /assets/batch-create-by-period`）与『复制上一条』（`CopyFromLastPanel`）是用户主动的编辑能力，与催办无关，保留原样。」它的立论前提是：账本存在「分期编辑」这一正当需求，这两个入口只是便利手段。

这个前提今天不再成立。账本模型已收敛为**时点快照 + 更正链**：`assets` 是带真实观测日的快照行，改值只能追加新行并以 `superseded_by` 指向（`backend/services/asset_service.py:672-709`），`assets` 表没有 `period` 列，账期退化为查询/分组参数（`backend/routers/assets.py:71,313,715,733`）。

同一时期，元数据（标签、备注）的归属问题也浮出来：标签早已挂在资产项（ADR-0019 D7「标签挂项不挂记录，一次标注覆盖全历史」），而备注根本不存在；记录页除批量打标外没有任何单条元数据入口。

## 2. 决策

**D0 备注与标签挂在资产项，不下沉到记录行。**
`asset_item_tags`（ADR-0019 D7）已确立「标签挂项不挂记录：一次标注覆盖全历史」。本期把备注也放进同一层：新增 `asset_items.note TEXT NULL`，单条可编辑、允许多行、上限 500 字符。
理由：记录行是时点快照且 write-once（改值走追加新行 + `superseded_by`），元数据若挂记录行，一次更正就丢一次，同一资产要重复维护 N 份。
否决：记录级 `record_tags` + `assets.note`（更正即丢、重复标注）；新建 note 历史表（备注是叙述性文字，不是口径判定；`asset_item_attr_history` 的 `dim` 白名单也不含 note）。

**D1 两个入口退役**：「批量按账期添加」与「复制上期」连同端点、service、前端面板、客户端方法、测试与审计契约一并删除。

**D2 理由一（主论点）：入口生产的是合成时点，不是编辑便利。**
`batch_create_by_period` 调 `period_service.get_representative_date`（调用点 `backend/services/asset_service.py:1471,1485`）把整个账期折叠成一个代表日写入 `asset_date`；`copy_from_last_period`（`:941`）把上期行原样搬到本期日期。二者写入的行在数据层与「那天真实观测到的余额」不可区分（`assets` 无来源列）。在一个以真实观测时点为准的账本里，这不叫分期编辑，叫**批量造时点**。

**D3 理由二（次论点）：维护成本落在一条没有真实用户的路径上。**
两个入口各占一条审计契约（`backend/services/audit_contract.py:368` traced、`:372` exempt）、各自的覆盖度断言（`backend/tests/test_audit_coverage_ledger.py` 中「by-period 头行唯一性 / `via` 标记 / `count == created_count` 三类）与专属测试文件。删除后这些成本同步消失；保留则必须永久维护。

**D4 理由三（事实）：业主已不再按账期录入。**
作为本系统的唯一用户，业主自述现按实际观测日逐条录入，不再使用账期成批录入。**注意：这是业主自述，不是埋点统计** —— 开发库为重建库，`audit_log` 无这两条端点的历史痕迹，无法构成使用率证据，故本 ADR 不引用任何使用率数字。

**D5 账期语义不整体废止。**
`backend/services/period_service.py` 整文件保留（`analysis` / `alert` / `proportion` / `signal` 仍在调用），账期只是降级为「分组 / 展示参数」。本 ADR 退役的是**成批造时点的入口**，不是账期概念。

**D6 历史数据不清洗。**
已由这两个入口写入的行都是合法账本事实，且无法按来源区分（无来源列），因此不做删除、不做标记、不做回填。

## 3. 后果

- **能力净损失（明示承认）**：录新一期同类资产不再有任何复制便利，只能逐条录入（新录入支持 `asset_item_id` 预填）。业主已裁决不补「从此项再录一条」的捷径，若日后需要，须按「真实观测日录入」重新设计，不得恢复原入口。
- **审计覆盖净损失**：删除 by-period 头行唯一性、`via` 标记、`count == created_count` 三类断言；审计契约表净减两个端点、新增 `note_update` 一个。具体计数只记入 `CHANGELOG.md` 与实现票，不写进本 ADR（数字会过期，过期的数字会被当成权威）。
- **口径不受影响**：净值权威仍是 `analysis_service._sum_as_of` 单点；删的是写入入口，不是合计出口，`test_total_consistency.py` 登记的合计出口不变。标签维度是分桶维度、允许重叠，**不登记**为合计出口（只做桶内自洽断言）。
- **元数据写入收敛到一个入口**：备注只经 `PUT /api/asset-items/{item_id}/note` 写入（与审计同事务、不进 `asset_item_attr_history`）；标签沿用既有端点。二者语义都是项级，改一次覆盖该资产全部历史记录——界面上以「进入资产项」的独立面板承载，记录行保持只读。
- **不再有「按账期批量补录」的暗径**：任何「补齐某一期」的需求必须落成真实日期的逐条记录。
