# ADR-0013：C3 建议闭环与审计 hash-chain——建议隔离区、确定性门、逐行链＋日封存

**状态**：**已接受（2026-10-29 冻结）**。配套 spec：`.scratch/phase3-advisor/spec.md` v1.0（已冻结）。本 ADR 同时**修正 ADR-0007** 中「`prev_hash` 恒 NULL、三期以一次性脚本回填」的时序条款（该条款本身即指向本期）；不改 ADR-0007 的 append-only 双层强制。**修订（2026-11-04，已接受）**：D6 的门项数 **10 → 9**（8 blocking + 1 warning），`GATE_DATA_PARTIAL` 退役，见 **ADR-0020 D2**。
**上游**：`docs/design/business-architecture.md:139-150`（R-23~R-30）、`:194`（F3）、`:200-207`（不变量）、`:242-243`（拍板 4/5）；`docs/design/system-architecture.md:33-37`（依赖图）、`:59-61`（建议聚合）、`:76`（F3 时序）、`:80`（慢管线）、`:85-90`（四区）、`:97-101`（信任架构）、`:129-133`（ADR 候选 5/6/9）、`:177-178`（拍板 2 hash-chain 时点 / 3 慢管线）；`docs/design/metric-system.md:147-164`、`:167-178`；前置 ADR-0007/0010/0012 与三期-1/2 实现。

## 1. 背景与问题

- 三期-1/2 已交付「目标版本＋达成度」与「双阈值＋域级灯」，F2 的「偏离→信号」已闭环；但**建议闭环（F3）完全缺位**：无建议载体、无信息集、无门、无审阅记录（`business-architecture.md:139-150`、`system-architecture.md:76`）。
- 即将出现的**第一类机器产出**经人批准后进入「决策记录」；此前 `audit_log` 全部由人的动作产生，篡改动机与审计价值同时上升（`business-architecture.md:203`、`:207`）。系统架构拍板 2 已冻结「hash-chain 在建议闭环上线前引入」（`system-architecture.md:177`），但实现形态未定。
- 现状三个具体缝：
  1. `audit_log.prev_hash` 自 0009 起**恒 NULL**（`models.py:559`、`audit_service.py:87`），且 0009 的 `audit_log_no_update` 触发器使「事后批量补列」不可行（`0009_audit_log.py:39-44`）。
  2. 0016 迁移直接 `INSERT INTO audit_log` 绕过 `audit_service`（`0016_asset_item_owner_changes.py:187-219`）——「单点发射」在迁移目录存在**已知例外**，链化后必须显式处置。
  3. 建议区在库内**尚不存在**（`database-map.md:17`：「暂无（三期规划）」），四区隔离只有文字约束，无表、无触发器、无测试。
- LLM 已有一套 OpenAI 兼容客户端与供应商配置（`llm_verification_service.py:139-166`、`routers/llm_providers.py:70-171`），但**没有**「让模型产出可校验建议」的约束机制：自由文本无法机器验证「数字来自可信源」。

## 2. 决策

**D1 边界：采纳 ≠ 落账，且建议粒度止于配置层。** 采纳只写「人的决策记录」；任何账本变化必须由人另行触发 F1/口径变更用例（独立事务、独立审计）。建议项 `subject_kind ∈ {attribute, goal, threshold, narrative}`，**不产出逐资产项买卖指令**。理由：不变量 4（`business-architecture.md:203`）、F3 关卡（`system-architecture.md:76`）、非目标「无人工确认的全自动记账」（`:218`）。

**D2 建议隔离区＝7 张表，账本区零 FK。**

| 表 | 区 | 写保护 |
|---|---|---|
| `advisor_info_sets` / `advisor_info_entries` | 建议隔离 | 触发器拒 UPDATE/DELETE |
| `advisor_suggestions` / `advisor_suggestion_items` | 建议隔离 | 内容列**生成期外**不可改；项表 write-once |
| `advisor_decisions` | 建议隔离 | append-only（拒 UPDATE/DELETE） |
| `advisor_jobs` | 会话/任务 | 可清理（>7 天终态） |
| `advisor_settings` | 参考 | 单行，变更入审计 |

隔离手段：①`advisor_` 前缀 ②只对 `goals/goal_versions`（参考区）建 FK；账本实体仅以 `source_ref` **文本**引用 ③建议区写函数集中在 `services/advisor/` ④反向依赖禁止（`ledger/valuation/planning` 不导入 `services.advisor`）。依据 `system-architecture.md:88`、`database-map.md:17`。

**D3 「advisor 不可写账本」用三重结构保证，不用约定。**

1. **端口**：`services/advisor/ports.py` 只暴露 `ReadModel`（只读数字视图）与 `LlmGateway`；`advisor` 包不 import 任何账本写服务/账本模型。
2. **依赖测试**：`ast` 扫描 `services/advisor/**` 与 `routers/advisor*.py`，禁止 import `asset_service / principal_service / transfer_service / lineage_service` 与账本模型 `Asset / AssetItem / AssetItemName / AssetItemOwnerChange / PrincipalChange / TransferEvent / LineageLink`。
3. **行为测试**：生成→采纳→执行备注全链路前后，账本五表行数与最大 `id` 不变；建议路由集合中不存在写账本动作。

依据：`system-architecture.md:37`（依赖图上不存在写端口路径）、`:63④`、`:97`（导入边界检查＋测试锁定）。**为什么不用运行时权限/开关**：单进程无权限层，开关可被误开；依赖图不可达是编译期事实，测试是它的证据。

**D4 信息集＝write-once 行式条目＋封闭键空间＋`payload_sha256`。** 头表存 `as_of/builder_version/entry_count/payload_sha256`；条目表 `UNIQUE(info_set_id,key)`，键空间由 `builder_version` 定义（`meta/nw/coverage/appreciation/returns/goal/alloc.<dim>.<id>.*/signal.*`）。`label` 只放通用类目名，不含账户/机构/持仓名。理由：R-26 要「事后重放建议时点信息集」（`business-architecture.md:143`）；行式使门可逐条校验（引用存在、值一致），JSON blob 只能整体信任。

**D5 LLM 只拿「缩放值＋占位符语汇」，输出结构化 JSON。** 输入条目金额按「万元/1 位小数」、比率 4 位、状态枚举（`value_scaled`）；输出正文的数字**只允许** `{{info.<key>}}` 占位符，服务端用权威条目值插值渲染（`summary_rendered` / `rationale_rendered`）。于是「LLM 不做算术、数字来自可信源」由**语法**保证，而非事后审计（不变量 5，`business-architecture.md:204`；`metric-system.md:164`）。副作用：模型看不到精确净值 → 隐私面收窄（§4 风险）。
**显式降级**：本期不联网检索，`meta.market_basis="model_knowledge"`＋降级注记；R-23 的「优先联网检索」记 ◐（`business-architecture.md:140`）。

**D6 确定性门＝10 项纯函数检查（8 blocking + 2 warning），失败即终态。** blocking：`GATE_SCHEMA`、`GATE_INFO_SET_SEALED`、`GATE_REF_EXISTS`、`GATE_NUMERIC_PROVENANCE`（无数字字面量）、`GATE_PLACEHOLDER_RESOLVES`、`GATE_GOAL_ANCHOR`（有 active 主目标时版本必须对齐）、`GATE_FRESHNESS`（`as_of` 距今 ≤45 天）、`GATE_NO_EXECUTION`（枚举封闭＋执行意图词）；warning：`GATE_THRESHOLD_SOURCE`、`GATE_DATA_PARTIAL`。门是 `advisor` 内独立纯函数组件、不共享 LLM 客户端（`system-architecture.md:101`）；失败后人工不可放行（`:76`）。

**D7 触发三型＋`dedupe_key` 唯一＋冷却；自动触发默认关闭。** 手动 `manual:<uuid>`；信号 `signal:<domain>:<as_of>` / `signal:event:<rule_id>:<period>`（源＝B4 红灯/上升沿异动）；定时 `sched:<date>`。`advisor_settings.auto_enabled=0` 种子，`cooldown_days=7`。理由：单用户系统里「自动生成」是打扰与成本，不是能力；关闭不损害闭环（手动始终可用）。依据 `system-architecture.md:76`、系统架构拍板 3（进程内任务，`:178`）。

**D8 状态机七态，终态集合显式。** `generating → {awaiting_review | gate_failed | generation_failed}`；`awaiting_review → {accepted | rejected | expired}`；`accepted` 不因执行备注改变状态。终态 `{generation_failed, gate_failed, accepted, rejected, expired}` 一律拒绝再次裁决（409）。对照设计稿「生成→门(通过/失败)→待审→采纳/驳回→执行追踪→过期归档」（`system-architecture.md:60`）。

**D9 裁决 append-only＋部分唯一索引＋幂等。** `advisor_decisions` 拒改删；`UNIQUE(suggestion_id) WHERE action IN ('accept','reject','expire')` 兜底「一单一次终局」；`suggestions.status` 是**投影**，由同一服务函数在裁决事务内更新（一致性测试锁）。驳回 `reason` 必填。

**D10 链形态＝逐行 `prev_hash`（插入时计算）＋单行状态 CAS＋日封存＋库外锚。**
- `row_hash = SHA256(canonical_json([prev] + FIELDS))`，`FIELDS = occurred_at/actor/entity/action/row_id/before_json/after_json/evidence_ref/request_id/idempotency_key`；`before/after` 取库内已存文本原样，不重序列化。
- 首行 `prev_hash = GENESIS = SHA256("person_f.audit.genesis.v1")`；本行 hash 存于下一行 `prev_hash`（链尾在 `audit_chain_state.last_hash`）。
- 插入后 `UPDATE audit_chain_state SET last_id=?,last_hash=?,row_count=row_count+1 WHERE id=1 AND last_id=?`；`rowcount≠1` → 事务失败（`AUDIT_CHAIN_CONFLICT`）。
- `audit_chain_seals` 日封存（`prev_seal_hash` 自链），封存 hash 同时写应用日志与备份 `manifest.audit_head`——这是发现「整库回退」的唯一手段。
- **为什么不用批量窗口填列**：填列必需 `UPDATE audit_log`，与 0009 的 `no_update` 触发器正面冲突（`0009_audit_log.py:39-44`）；逐行计算零触发器改动、覆盖即时，封存只承担「外锚/回退检测」职责。

**D11 0018 一次性回填（改 `prev_hash`，不改语义列）。** 单事务内：建表→（状态行已存在则跳过）→临时删 `audit_log_no_update`→按 id 升序计算并 `UPDATE prev_hash`→写状态行→重建触发器→断言（行数/尾 id/无 NULL）。SQLite 的 DDL 在事务内可回滚，失败即整体回退；迁移前 runner 已自动备份（`db_migration_service.py:224-232`）。依据 ADR-0007「三期以一次性编号脚本回填启用」、ADR-0010 §6.2「C3 按冻结时点统一回填」。

**D12 迁移 0018/0019，均无 CLAIM、无 down；回滚靠启动 `ensure()` 续接。**
- 0018：`audit_chain_state`、`audit_chain_seals`＋触发器＋回填；0019：7 张 `advisor_*`＋写保护触发器＋`settings` 种子。
- 回滚到 0018 前：新行 `prev_hash=NULL`，校验器返回 `unchained_rows>0`；再升级时 0018 不重跑，由 `services/audit_chain.ensure()` 从链尾**只补 NULL 行**；若已链行与状态不符 → CRITICAL 并拒绝续接（需人工）。
- 回滚到 0019 前：表残留、旧代码不读不写。
- **初始化单点分两段**：`ensure_state_row()`（请求内可调，**空库**种 `(0, GENESIS)`，有行无状态则抛 `AUDIT_CHAIN_UNINITIALIZED`）与 `ensure_chain()`（**仅启动/迁移**，可临时摘 `audit_log_no_update` 做回填/续接）；`record()` 只调前者，避免在业务事务里做 DDL。
- 依据 `system-architecture.md:91`、`db_migration_service.py:111-135`、`:202-236`。

## 3. Considered Options（为什么不是别的）

| 议题 | 弃选 | 理由 |
|---|---|---|
| 建议存储 | 单表 + 全 JSON 列 | 引用无法逐条校验、无法 index、门只能整体信任；R-26 重放退化为「信一个 blob」 |
| 建议存储 | 9 表（+白名单/引用表/执行明细） | 白名单本期无消费方（外部引用一律 narrative）；执行明细违反业务架构拍板 4「轻量」 |
| 隔离 | 靠 code review 约定 | 无证据；一条 import 就能写账本。依赖测试把约定变成红灯 |
| 隔离 | 运行时权限/DB 账号 | SQLite 单连接单用户，无权限层可依；伪安全 |
| 数字策略 | 发送精确值 + 事后数字溯源 | 模型仍可能算错/编造；溯源门要么过宽（漏）要么过严（误杀），且精确净值外泄 |
| 数字策略 | 只发状态/灯，不发数值 | 模型无法判断量级，建议退化成语义空话 |
| 门 | 只校验 JSON schema | 满足不了 R-25「算术重算/引用可解析/与账本一致」 |
| 门失败 | 允许人工「强行通过」 | 破坏「门失败＝终态、账本侧不可达」；审阅人会习惯性放行 |
| 触发 | 默认开启定时生成 | 单用户场景＝噪声＋token 成本；关闭不损失能力 |
| 链 | 批量窗口填 `prev_hash` | 与 0009 append-only 触发器冲突，需把写保护改成可开关 |
| 链 | 不回填、链从切换点起 | 校验器需双模式（NULL 前缀＋锚摘要），历史行永不入链；ADR-0007/0010 已冻结回填 |
| 链 | 引入外部公证/时间戳服务 | 自托管单用户；新增外部依赖与隐私面，收益（防全链重算）超出威胁模型 |
| 回填 | 修改历史迁移 0016 使其走 `record_sqlite` | 已登记迁移不重跑，改动只影响全新库；真正需要的是「今后单写者」测试，而非改史 |

## 4. Consequences

**正面**

- R-23~R-27 一次闭环：信息集可重放、引用可机器校验、门不可绕过、采纳留痕且**不落账**。
- 「LLM 不做算术」从口号变成语法：模型输出中的数字只能是占位符。
- 隔离区从「文档里的一句话」变成「表＋触发器＋AST 测试＋行为断言」四层证据。
- 审计链在建议闭环上线前就位（系统架构拍板 2），且**首日即覆盖** C3 的生成/裁决行；封存＋备份 manifest 使「整库回退」可被发现。
- 迁移面收敛：0018 两表＋回填、0019 七表＋触发器；无 CLAIM、无 down、无数据改写（除 `prev_hash` 元数据列）。

**负面/代价**

- **回填改写了历史行的 `prev_hash`**：形式上是「100% 行的 UPDATE」，实质只补完整性元数据；必须在 ADR/CHANGELOG 明示，且不再有第二次。
- **模型看不到精确金额**：文案自然度下降（「约{{…}}」而非具体数），需要 prompt few-shot 校准；若业主更看重文案，可切到「精确值＋溯源门」（§9.4-3 备选）。
- **占位符门很硬**：模型偶发写出数字即整单失败；靠重试 1 次＋few-shot 缓解，不放宽门。
- **`status` 为投影**：`advisor_decisions` 才是真源，存在「投影与真源不一致」的理论窗口；用单服务函数＋一致性测试（同事务）压到最小（与 `goal_versions.status` 同类取舍）。
- **自动触发默认关闭**：用户不点就没有建议；「主动通知/推式投递」仍是缺口（`system-architecture.md:152`）。
- **无联网检索**：市场面判断来自模型常识，时效性不可保证；已用 `market_basis` 显式降级，但 R-23 只算 ◐。
- **链的能力边界**：能发现「不一致」，不能阻止有库写权限者重算全链；文案必须避免「不可篡改」的绝对表述。
- **0018 依赖 `idempotency_key` 列**（0010）：更老的库需先补齐，迁移显式报错而非猜测。
- **既有测试改动**：`test_audit.py:48`、`test_goals.py:348`（`prev_hash` 断言）、`test_identity.py:93`（编目区间）、`test_migrations.py`（编号区间）；`/api/audit-log` 响应加性字段 `prev_hash`。

## 5. 拍板结果（待定；推荐默认见 spec §9.4）

1. 链是否回填历史行 → **回填**（一次性、单事务、只改 `prev_hash`）。
2. 封存外锚 → 日封存＋应用日志＋备份 `manifest.audit_head`。
3. LLM 数字策略 → **占位符＋服务端插值**（模型不接触精确金额）。
4. 门清单与级别 → spec §5.2 的 8 blocking + 2 warning。
5. 自动触发默认 → **关闭**（`auto_enabled=0`），冷却 7 天。
6. 建议过期 → `created_at + 30` 天（代码常量）。
7. 执行追踪形态 → 采纳后独立 `execution_note`（不改状态、不记金额）。
8. 市场面降级 → `market_basis=model_knowledge`＋显式注记（不接搜索 API）。
