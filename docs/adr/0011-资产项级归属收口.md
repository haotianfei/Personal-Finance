# ADR-0011：资产项级归属收口——共有归属 + append-only 变更史

**状态**：已接受（2026-10-29，默认冻结；上游 ADR-0010 §5、`docs/design/system-architecture.md:55`、`docs/design/metric-system.md:127-133`）。**修订（2026-11-04，已接受）**：决策 1 的「不设 `asset_items.owner_id` 当前列」由 **ADR-0020 D3** 取代——当前归属以列为唯一真相源，`asset_item_owner_changes` 降为纯审计流水。

**背景**：业务架构 R-31/R-32 要求「每条记录可标注所有者 / 共用资产有明确归属规则」，拍板 6 定「家庭池虚拟成员、不做比例拆分、视图仅本人可见」（`business-architecture.md:152-155`、`:244`）。现状把 owner 挂在快照行，同一资产项可多值、无史；系统架构要求「共有归属：资产项聚合内属性（当前值 + 变更留史）」（`system-architecture.md:55`）。ADR-0010 的 member scope 与四期成员视图都依赖此收口。

**决策**：

1. 新增 `asset_item_owner_changes`（`asset_item_id`、`owner_kind∈member|family_pool`、`owner_id`、`effective_date`、`reason`、`origin`、`created_at`），append-only 触发器；当前值=最新行，无行=未标注；不设 `asset_items.owner_id` 当前列（单真源）。
2. 家庭池=`owner_kind="family_pool"` + `owner_id=NULL`；不建虚拟属性行；owner 字典禁止「家庭池」名称。
3. 写路径统一 `POST /api/asset-items/{id}/owner`；旧 `assets` 批量/单条 owner 字段在兼容期翻译为 item 级；截图/导入只对新建项写初始归属，不覆盖已有归属。
4. 读路径 item 级优先、记录级回退（一个兼容版本）；列表过滤/导出/记录页显示 item 级；响应增 `owner_kind`（additive）。
5. 迁移 0016 从最新 active 快照回填，`effective_date=迁移日`，`origin=migration`；冲突确定性 tie-break 并出只读清单；不 UPDATE/DELETE 旧表。
6. owner 删除保护同时检查 `asset_attributes` 与 `asset_item_owner_changes`（以及未来 `goal_versions.scope_owner_id`）。

**Considered Options**：双写（弃：双真源）；只在读时合并（弃：无史、无法支撑四期）；建 `asset_owners` 新表（弃：owner 已是 `attributes` 字典，重建会破坏既有 CRUD/导入）；把 owner 放 `asset_items` 当前列（弃：与史表双源）。

**拍板结果（2026-10-29，同 ADR-0010）**：采纳本方案（合成 `owner_kind`、不双写、接受回滚降级）；与 ADR-0010 同日发布。

**Consequences**：四期成员视图/目标有数据基础；兼容期双读与回滚降级（§5.5）；旧 `asset_attributes` owner 行保留为历史/回退，不删除；owner 改名安全（引用 id），历史显示用当前名（审计 before/after 可查旧名）。
