# ADR-0012：C2 双阈值与 B4 域级汇总——判据解析、有效阈值、事件化异动

**状态**：**已接受（2026-10-29）**；§5 七项按推荐默认拍板。配套 spec：`.scratch/phase3-c2/spec.md` v1.0（冻结）。
**上游**：`docs/design/metric-system.md:91-110`、`:147-178`；`docs/design/business-architecture.md:124-137`（R-15/17/19/20/21/22）；`docs/design/system-architecture.md:21-22`、`:57`、`:73`、`:134`、`:152`；前置 ADR-0010/0011。

## 1. 背景与问题

三期-1（C1）已落地并冻结「C1 值 + 无判据 → `grade=null`」，并明确把「目标进度偏离、B4 汇总、异动定义」留给三期-2（`docs/adr/0010-目标版本与达成度口径.md:159-171`、`:228-238`）。当前：

- 配置偏离只有**单阈值**（`allocation_targets.alert_threshold`），超阈值一律黄；R-21 要求「绝对 pp 或相对 % 取先触发」的**双阈值**与方向引导（`business-architecture.md:136`；`metric-system.md:67`）。
- 阈值解析存在**两套实现**：页面侧 `allocation_service._calculate_deviation_metrics`（`allocation_service.py:214-263`）与指标面 `metric_service._deviation_rows`（`metric_service.py:570-601`），已具备漂移条件。
- B4 只有单规则结果（`alert_rules`），没有「单灯 → 子域灯」的汇合，也没有「异动」的事件语义（`metric-system.md:71`、`:110`；`business-architecture.md:125`）。
- `allocation_targets` 就地可变、无审计（`models.py:76-88`；`routers/allocations.py:16-100`），与不变量 8「任何写入可回答谁/何时/依据什么」有缝（`business-architecture.md:207`）。

## 2. 决策

**D1 带型**：C2 使用 `dual_threshold`（黄/红）；C1 仅 `goal_required_annualized` 使用 `dual_threshold_one_sided`（黄/红，单向）。其余指标本期不判灯。边界一律**严格大于**（等于阈值不触发），沿用既有契约（`tests/test_metrics.py:361-366`）。

**D2 有效阈值（取先触发）**：把相对阈值折算为等效 pp，取更敏感者：

```
eff_y = min(abs_y, target% × rel_y/100)   # 相对适用时
eff_r = min(abs_r, target% × rel_r/100)
rel_on = target% >= 10.00                 # 相对判据适用下限（代码默认）
```

红档兜底：`abs_r = alert_threshold_red or 2×abs_y`；`rel_r = 2×rel_y`；`band.source` 必须标注 `code_default`。相对判据的下限只关闭适用性，不改变「取先触发」语义（`metric-system.md:101`）。

**D3 判据来源优先级**：① GoalVersion（`target_rate_annual`）→ ③ `allocation_targets` 行 → ④ 代码兜底；② 配置框架实例（Vanguard 三元组）本期未建、仅预留覆盖位（`metric-system.md:104`；`system-architecture.md:57`）。阈值只由人设定；系统不自动调阈值（不变量 6、R-30）。

**D4 C1 判灯口径**：`required_annualized`（`goal_service.compute_progress`）对 `target_rate_annual`：黄=`required > target_rate`，红=`required > 2×target_rate`；`target_rate` 为空或 `≤0` → 无判据（`grade=null`）；`required=null`（阻断）→ ⚪。**不重写** `criterion_json`（`goal_service.py:111-120`），判据读时解析。

**D5 域定义与聚合**：域=注册表 `domain`（B1/B2/B3/C1/C2/底座），固定顺序；B4 是汇总者不是域；**不设全局灯/总分**。聚合：红 > 黄（含事件）> ⚪ > 绿；`grade=null` 不阻断绿但回传 `judged/total`；`gray`（降级）阻断绿；同域 ≥2 红信号（item 或 C2 行）→ `needs_diagnosis=true` 并列红项（`metric-system.md:110`）。

**D6 异动=事件**：源=现有 `alert_rules` 检查结果；只取**上升沿**（本期触发、上一有数据账期未触发）→ `status="new"`；连续触发 → `ongoing`；去重键 `(rule_id, period)`；静默期=「未回落不重复报」，**零落表**、读时重算。默认严重度 yellow；红只来自带型判据（`business-architecture.md:125`；`alert_service.py:205-247`、`:479-505`、`:508-585`）。

**D7 迁移**：0017 只给 `allocation_targets` 加两个可空列（`alert_threshold_red`、`relative_threshold`），无回填、无史表、无触发器；NULL 走代码兜底。阈值变更补审计＋幂等（不变量 8）。阈值版本化/史表延三期-4（`metric-system.md:106`）。

**D8 band_basis**：本期所有判灯 `basis="current"`；`as_of` 只移动取值锚点，不移动判据尺，历史请求在 `grade.note` 注明「判据为当期」。**不提供** `basis="as-of"`，直到阈值有变更史（三期-4）。

## 3. Considered Options（为什么不是别的）

| 议题 | 弃选 | 理由 |
|---|---|---|
| 红档来源 | 纯代码 2× 派生（零迁移） | 红档不可由人覆盖，违反「阈值由人定」；`band.source` 永远是默认 |
| 红档来源 | 本期建 append-only 阈值史 | 读/写/迁移三处改动，超出「小迁移」；三期-4 才消费 |
| C1 判据 | 时间线性进度偏差（5pp/25%） | 「线性推进」与 C1「不再投入的 CAGR」假设冲突，早期易给出误导性绿 |
| C1 判据 | 本期不判 C1 | R-17「目标进度偏离」落空，B4 三源缺一 |
| 域粒度 | B/C 主域（2 个） | 失去子域诊断粒度，违反「单灯→子域灯」 |
| 域粒度 | 新增 B4 域条目 | 自引用；B4 是汇总者（`metric-system.md:71`） |
| 绿档条件 | 全覆盖才绿 | B1/B2/B3 本期无判据，域灯长期 ⚪，汇总失去意义 |
| 异动 | 落事件表 + 时间窗静默 | 需新表/调度；读时可重算即幂等，先不引入 |
| 异动 | 视为状态（常驻灯） | 无法回答「刚发生了什么」；且会长期污染域灯 |
| 全局灯 | 汇总为单一四态灯 | 易被读成「健康总分」，与约束冲突（`metric-system.md:74`、`:178`） |

## 4. Consequences

**正面**

- R-21 闭环：黄/红双阈值、绝对/相对取先触发、方向性引导；页面与指标面共用一套解析，消除漂移。
- R-17 信号层闭环：配置偏离、目标进度偏离、异动 → 子域灯；异动有事件语义且零存储。
- 迁移面最小：两列、无回填、revert 可启动；既有 `alert_rules`/`goal_versions` 零改动。
- 判灯诚实：无判据 `grade=null`、降级不给绿、历史 as-of 明示「判据为当期」。

**负面/代价**

- `criterion_json` 与 B4 判据**不同源**（前者激活时快照、后者读 `target_rate_annual`）：审计可解释，但不是单一快照；三期-4 重放时需同时读两处。
- 阈值无变更史：历史 as-of 不能给 `basis="as-of"`，复盘能力受限；已在响应中显式降级。
- 既有契约变更：`allocation_deviation` 的 kind 与红档、`goal_required_annualized` 由无判据变可判；需同步测试/前端（spec §5.4）。
- 相对判据下限、红档 2× 兜底是代码默认值，需人可覆盖；默认值本身需拍板。
- 异动依赖用户维护的 `alert_rules`；规则缺失/过噪会直接影响域灯质量。

## 5. 拍板结果（2026-10-29，全部按推荐默认）

1. C1 判据口径 → required vs `target_rate_annual`（黄=超过，红=2×；空/≤0 不判灯）。
2. 红档来源 → 0017 人设列 `alert_threshold_red`（空=2×黄，来源标注 code_default）。
3. 相对判据适用下限 → 目标权重 ≥10%。
4. 域粒度与绿档条件 → 注册表 `domain` ＋仅可判项判绿＋judged/total；gray 阻断绿。
5. 全局灯 → 不设，仅 `summary` 计数。
6. 异动严重度与静默 → 默认黄＋上升沿＋未回落不重复报＋零落表。
7. 阈值留史时点 → 本期列＋审计；史表延三期-4。
