# ADR-0015：零额快照合法化——金额值域改为 `amount >= 0`

**状态**：已接受（2026-10-29，业主拍板「0 = 合法测量」）。
**上游**：`CONTEXT.md:14`（金额恒为正）、`docs/design/database-map.md`（§1/§5）、`docs/design/system-architecture.md:48,93,127`、`docs/design/business-architecture.md:90`（R-1）；ADR-0002（金额恒正 + side）。
**下游**：`.scratch/db-audit/audit-2026-10-29.md`；待办迁移 0023（补 `CHECK(amount >= 0)`）。

## 1. 背景与问题

数据库审计（2026-10-29）发现三处规范与实现正面冲突：

1. **三条写路径主动写 0**：补录 `mode=zero`（`backend/services/account_reminder_service.py:149-152`，且为默认模式）、截图 `zero_names`（`backend/routers/screenshots.py:455`）、CSV 导入（`backend/services/import_service.py:251`）。
2. **库内实际存在 982 条 `amount=0`**（全部 4193 行的 23.4%），其中 977 条是当前 active 最新行；57 个资产项现值为 0，其中 48 项曾有正金额、9 项全史为 0；912 条零值行无凭证。
3. **规范侧声明「金额恒正」**，存储层却无任何 `CHECK`（仅 `transfer_events.amount > 0`），所以 0 一路畅通。

> 后记（ADR-0018）：补录通道（`zero-fill` / `fill-preview`）已于 2026-10-31 退役，第 1 条记的是当时的实现事实；现行主动写 0 的路径只剩截图 `zero_names` 与 CSV 导入两条。

同时确认：库内**没有任何负金额行**，也没有一条 0 值行被用于表达"未知/未测量"以外的含义——即"0 到底算不算一次测量"此前从未被明确拍板。

## 2. 决策

**D1 值域**：快照金额（`assets.amount`）值域改为**非负**：`amount >= 0`。`0` 是**合法测量值**，语义固定为「该快照日该资产项余额为零」。

**D2 负数仍禁止**：`amount < 0` 仍属非法。收支方向继续由 `side ∈ {asset, liability}` 表达（沿用 ADR-0002），不得用负号表达负债。

**D3 补录零值的地位**：`zero-fill`（默认 `mode=zero`，已于 ADR-0018 退役）、截图 `zero_names`、导入写出的一律记为 measured 0，与手工录入的 0 **不做区分**。本轮**不引入 provenance 列**；若将来需要区分"真实清零"与"补录占位"，另立 ADR。

**D4 as-of 沿用语义不变**：0 与其它金额同等参与「取该日期（含）之前最新一条记录」；最新值为 0 时沿用值即为 0，读端**不做特殊回退**。

**D5 历史不动**：982 条零值行不删除、不覆盖、不追加更正——账本 write-once 语义优先。9 个全史为 0 的资产项若要退出统计，走 `asset_items.status='archived'`，与金额无关，另行裁决。

**D6 落地层次**：本轮只改文档口径（CONTEXT + 设计文档 + database-map）；存储层 `CHECK(amount >= 0)` 由结构迁移 0023 补，不与数据清洗混做。

## 3. 后果

- 净值/覆盖度/沿用口径**均不变**：0 一直是测量值，只是此前与文档矛盾。
- 文档需同步 4 处口径：`CONTEXT.md`、`system-architecture.md`、`business-architecture.md`（R-1）、`database-map.md`。
- 已知限制：历史 982 条零值无法回溯区分"真实清零"与"为满足覆盖度而补 0"，如需追溯只能依赖 `audit_log`（起点 2026-10-01，覆盖不足）。
- 0023 的 `CHECK` 必须写 `amount >= 0`，**不可**写 `> 0`，否则拒绝三条现有写路径。
- 迁移 `transfer_events.amount > 0` 保持不变：转移事件金额必须为正，与快照零额语义不同。
