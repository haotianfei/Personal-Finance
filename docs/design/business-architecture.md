> **设计最高准则（置顶，详见下节）**：系统的原子是一个资产；系统关注单个资产的全生命周期（过去/现在/将来）。一切域、聚合、流程、契约设计均须可回溯于此。

## 设计最高准则（Supreme Design Principle）

> **SDP-1 资产原子性**：系统的原子是**一个资产**；系统由众多资产构成，是资产集合的容器与视图。

> **SDP-2 全生命周期聚焦**：系统关注的是**单个资产的全生命周期——过去、现在、将来**：
> - **过去** = 历史记录与凭证（不可改写、永久可溯）；
> - **现在** = 现状与升值（市值、累计投入本金、升值额/率）；
> - **将来** = 目标、配置与建议（对准未来收益目标）。

> **SDP-3 可回溯性约束**：全系统一切设计——业务域与子域划分、领域聚合、业务流程、前后端契约——**都必须可回溯到 SDP-1/SDP-2**。任何无法回溯到「一个资产的生命周期」的设计元素，须给出手写豁免理由，否则不予采纳。

> **SDP-4 效力范围**：本准则是最高层设计约束，业务架构（本文档）与后续系统架构阶段（上下文边界、聚合契约、数据模型、API 设计）共同引用；下游任何决策与本准则冲突时，以本准则为准，修改准则须经用户显式拍板并留史（升级不降级）。

## 设计基础：服务对象与原子（置于 SDP 之后、§0 之前）

### 1. 服务对象形式化

**画像分层**：①**资产持有者本人**＝决策者兼唯一使用者，一切裁决权归其；②**家庭成员**＝数据主体与被盘点视角，非使用者、无账号；③**机器**（识别引擎/AI/校验门）＝信号源，不是服务对象。

**需求内核**（一条链）：认清现状 → 升值度量 → 目标对齐 → 引导 → 复盘。

**由服务对象决定的产品性格**：单用户、自托管、人裁决、无账号体系、录入摩擦最小化。
**为谁**：有资产、有管理资产生命周期需求的人（从本人起步，演进到家庭盘点）。**不为谁**：日常记账用户、多操作员家庭（需要权限体系者）、期望全自动理财者。

### 2. 原子形式化

**『一条资产』＝资产项（稳定身份）＋三段生命周期**：过去＝记录与凭证；现在＝市值与累计投入本金；将来＝目标、配置、建议（SDP-1/2 的展开）。

**三个必答追问**：
- **① 身份边界（什么算同一条资产）**：身份＝「机构渠道下的产品」，与显示名解耦——改名不改身份（旧名留史）；**同标的多渠道＝多条资产项**（凭证与本金按渠道独立，合并会破坏追溯），跨渠道聚合放到视图层；合并/拆分/产品改版＝旧项清零归档＋新项创建＋**血缘链接**关联，历史不删。
- **② 原子之外的关系层**：原子间存在三类关系，缺则生命周期讲不圆——**内部买卖联动**（两资产项间的转移事件，净值不变，本金口径随资金移动）；**共有归属**（资产项 ↔ 成员/家庭池）；**归集挂靠**（资产项 ↔ 账户/来源组，N:M）。关系是原子的连线，不是新原子。
- **③ 原子之上只有视图与归集**：组合、账户、家庭、目标进度皆为**聚合视图**——只读原子与关系，不产生新账本事实、不引入新生命周期。

### 3. 全系统设计骨架（推导链 → 承载核对）

**原子 → 关系 → 视图 → 时间 → 决策 → 信任**。

核对 v1.0：原子（A1/§3 聚合）— 已承载；视图（B1/B3/D2）— 已承载；时间（账期/快照日/glide path/复盘时点）— 已承载；决策（F1~F3 关卡 + 不变量 1/4/6）— 已承载；信任（A3 + 不变量 2/3/5/8）— 已承载。

**唯一缺口＝关系层未显式建模**。最小修订（只列差异）：
- §2 增补 **R-34**：内部买卖以「联动转移事件」登记（关联两资产项，本金随资金移动），不产生流水明细；
- §2 增补 **R-35**：资产项支持血缘链接（改名/合并/拆分/改版），历史只追加；
- §3 对象表增「转移事件」「血缘链接」「共有归属」三个关系对象，归「过去→现在」段。

## 0. 使命锚点

使命：用最低录入成本，建立可信、可追溯、能指导决策的个人资产账本，升级为家庭资产盘点。使命条目：①个人→家庭；②配置引导；③AI 调优与复盘（只出建议，不自动执行、不自动落库）。原则：可信 > 丰富；摩擦最小化；机器给信号、人做裁决；隐私自托管；演进有据。痛点：P1 录入麻烦；P2 本金/收益不分；P3 配置靠感觉；P4 无凭证不可查。

## 1. 业务域总览（两级结构）

| 主域 | 生命周期段 | 子域 | 一句话职责 |
|------|-----------|------|-----------|
| **A 账本与凭证** | 过去 | A1 快照账本 / A2 采集与录入 / A3 凭证·对账·审计 | 权威事实与可信底座 |
| **B 现状与升值** | 现在 | B1 净值现状 / B2 本金与升值 / B3 占比与流动性洞察 / B4 预警信号 | 现在值多少、赚了多少、离目标多远 |
| **C 目标与增值** | 将来 | C1 未来收益目标 / C2 配置引导与再平衡 / C3 AI 调优建议 / C4 复盘与反哺 | 目标设定 → 引导 → 建议 → 闭环 |
| **D 家庭盘点** | 扩展维度 | D1 成员归属 / D2 家庭视图 | 生命周期沿成员维度归集 |

数据可信底座不设独立主域，落位于 A2/A3，以全局不变量（§5）约束 A~D。

## 2. 子域能力与需求条目

### 主域 A：账本与凭证（过去）

**A1 快照账本** —— 能力：快照登记、身份管理、属性分类、更正。
- **R-1** 以「资产项 + 快照日期 + 金额（非负；0=该日余额为零，见增补记录 v1.3 / ADR-0015）+ 资产/负债侧」为最小账本事实，支持手工/截图/批量导入多路录入。
- **R-2** 任一快照日可还原净资产：每资产项取该日（含）前最新记录。
- **R-3** 资产项可挂多维属性（类型/账户/流动性/成员），属性成层级树。
- **R-4** 录错不改写历史，以追加记录 + 审计痕迹更正。
- **R-35** 资产项支持血缘链接（改名/合并/拆分/改版），历史只追加。
- **R-37** 资产项清零后可归档（终态）：默认不入现状视图，历史与复盘永久可查，不删记录。

**A2 采集与录入** —— 能力：识别、校正、待录入裁决（P1 直接对策）。
- **R-5** 录入摩擦最小化：最近值预填、待录入清单一次确认、可复用校正规则。
- **R-9** 本金口径的每次变动是人裁决的值，附凭证或原因标注，可追溯。

**A3 凭证·对账·审计** —— 能力：存证、血缘、对账、审计（P4 直接对策）。
- **R-10** 每条记录可追溯来源：截图凭证（原图+哈希）/ 导入批次 / 人工录入标注。
- **R-11** 凭证永久留存，独立于记录生命周期。
- **R-12** 对账：系统合计 vs 来源锚点金额，差异高亮供人裁决。
> 注：对账于 F1 采纳后即触发，亦可独立发起复查。
- **R-13** 审计日志：谁/何时/何操作/前值后值/来源凭证。

### 主域 B：现状与升值（现在）

**B1 净值现状** —— 能力：曲线、账期分组。
- **R-14** 净资产与升值曲线，按账期（日/周/月/季/年）分组。

**B2 本金与升值** —— 能力：本金口径、升值度量、收益归因（P2 直接对策）。
- **R-6** 每个资产项维护「累计投入本金」口径：只辨识外部本金投入/撤出与内生收益，内部买卖不改变本金；不做流水级记账。
- **R-7** 升值 = 当前市值 − 累计投入本金；给出升值额与升值率两个口径。
- **R-36** 口径变更带生效日期；历史期升值率按当时生效口径定格展示，可附当前口径对照，不改写历史。
- **R-8** 收益衡量双口径分工：时间加权（衡量策略）与资金加权/年化（衡量本人操作），以本金口径为输入、不依赖明细流水。
- **R-34** 内部买卖以「联动转移事件」登记（关联两资产项，本金随资金移动），不产生流水明细。
> 注：转移事件登记日即快照日，两资产项同步追加当日快照，保证净值与本金自洽。

**B3 占比与流动性洞察** —— 能力：多维占比、流动性分层（服务配置判断，不做消费分析）。
- **R-16** 按属性维度的占比分析与流动性分层。

**B4 预警信号** —— 能力：阈值监控。
- **R-17** 阈值预警（配置偏离、目标进度偏离、异动），预警是信号，处置在人。

### 主域 C：目标与增值（将来）

**C1 未来收益目标** —— 能力：目标设定、版本管理（使命②③之锚）。
- **R-18** 未来收益目标由人设定：形态候选为目标年化收益率 / 目标金额+期限 / 两者兼有；设定与变更记录理由、版本留史。
- **R-15** 目标进度视图：当前净值/年化 vs 目标，展示缺口与所需追赶幅度。

**C2 配置引导与再平衡** —— 能力：框架管理、引导、偏离监控（P3 直接对策）。
- **R-19** 配置引导以目标为锚：由目标 + 风险偏好推导建议配置，结果须可解释。
- **R-20** 多套业界配置框架并存（60/40、全天候、生命周期 glide path 等），记录选择理由；目标占比可随时间表演进，偏离始终对「当期目标」。
- **R-21** 偏离双阈值监控（绝对/相对取先触发），触发后给出「回调到目标」的方向性引导；系统不碰执行。
- **R-22** 风险预算类指标（回撤/波动率）分期引入，账本与本金口径成熟前不纳入。

**C3 AI 调优建议** —— 能力：市场情报、建议状态机、校验门（使命③）。
- **R-23** AI 依最新市场分析产出短/中/长期调优建议，建议须对准未来收益目标；市场分析优先 AI 联网检索。
- **R-24** 建议状态机：生成 → 确定性校验门 → 人工审批 → 采纳/驳回/过期，全程留痕。
- **R-25** 校验门：算术由系统重算（LLM 不做算术）、引用可解析、与账本现状一致性检查。
- **R-26** 每条建议附可解析引用（来源+时点），支持事后重放「建议时点信息集」。
- **R-27** 建议库与账本结构性隔离；进入计算的数字必须来自可信结构化数据源，AI 检索只服务叙事判断。

**C4 复盘与反哺** —— 能力：目标达成度对照、归因、反哺。
- **R-28** 复盘以目标达成度为锚：对照建议时点信息集、实际操作与其后走势，回答「离目标更近还是更远、为什么」。
> 注：采纳建议的执行追踪可松散关联其后相关落账（快照/口径变更），供「执行走样」归因取证。
- **R-29** 偏差归因四分类：市场变了 / 建议错了 / 没执行 / 执行走样。
- **R-30** 复盘结论反哺目标、配置与阈值——反哺只出建议，由人裁决。

### 主域 D：家庭盘点（扩展，使命①）

**D1 成员归属** —— **R-31** 每条记录可标注所有者（成员）；**R-32** 家庭共用资产（联名账户、共同负债）有明确归属规则。
**D2 家庭视图** —— **R-33** 成员/家庭两级净资产与升值视图；成员是数据维度而非账号体系。

**既有能力说明（现状参照、非设计约束）**：截图录入管线（来源组/识别引擎/AI 一致性校验/校正规则/采纳）、配置偏离分析、多维分析、预警均已落地，分别佐证 A2/B3/B4/C2；支出模块（固定支出/临时大额/分类/月负担）属记账式遗留能力，只读保留、不纳入规划。

> 注：R-34/R-35 为 2026-09-27 冻结时增补（原设计基础推演的最小修订）。

## 3. 领域模型核心聚合：一个资产的生命周期（SDP-1/SDP-2 的直接体现）

**聚合根 = 资产项**，其生命周期三段即服务最小单元：

```
        过去（主域A）              现在（主域B）             将来（主域C）
资产项 ─ 资产记录序列 + 凭证/批次 ─ 最新快照 + 累计投入本金 ─ 所属目标配置占比 + 关联建议/复盘
          （不可改写、永久可溯）      → 市值、升值额/率           → 偏离、引导、建议、达成度
```

| 对象 | 归属段 | 关键关系 | 生命周期 |
|------|-------|---------|---------|
| 资产项（聚合根） | 贯穿 | 1:N 资产记录；N:M 属性 | 创建 → 活跃 → 清零/归档（只追加不删史） |
| 资产记录（快照） | 过去 | N:1 资产项；N:1 凭证/批次；可携带本金口径扩展值（预留 cost_basis/units/nav 字段位） | 写入即不可改写；更正=追加+审计 |
| 累计投入本金（本金口径） | 过去→现在 | 挂靠资产项，随快照演进 | 设定 → 人裁决变更（附理由）→ 历史口径可回溯 |
| 转移事件 | 过去→现在 | 关联两个资产项；本金随资金移动，净值不变 | 人裁决登记 → 历史可回溯 |
| 血缘链接 | 过去→现在 | 关联旧项/新项（改名/合并/拆分/改版） | 创建即固定，只追加 |
| 共有归属 | 过去→现在 | 资产项 ↔ 成员/家庭池 | 设定 → 变更留史 |
| 截图凭证 / 导入批次 | 过去 | 1:N 记录 | 哈希固化，永久留存 |
| 来源组 / 校正规则 / 识别清单 / 校验比对 | 过去（会话性） | 挂来源组 | 采纳前不写入，会话结束即弃 |
| **未来收益目标**（独立聚合） | 将来 | 1:N 目标版本；被配置/建议/复盘引用 | 草案 → 生效（记录理由）→ 版本取代 |
| 目标配置 | 将来 | 引用属性维度 + 目标版本 | 生效 → 随 glide path 演进 → 版本留史 |
| 建议 | 将来 | 独立于账本；可关联目标 | 生成 → 校验 → 待审批 → 采纳/驳回 → 过期归档 |
| 复盘 | 将来（回看） | N:1 建议（批）+ 目标版本 | 发起 → 归因 → 结论 → 反哺提案 |

家庭维度（主域 D）是聚合上的**标注与归集视角**，不改变聚合边界。

## 4. 关键业务流程（按生命周期段标注）

**F1 录入→核对→入账**（过去 | A2→A1→A3）：采集 → 识别清单 → 校正规则 → 可选 AI 一致性校验 → 待录入清单人工逐行裁决 → 采纳写入 → 凭证挂链。**关卡：写入前必须过人。**

**F2 升值度量→目标对齐→再平衡**（现在→将来 | B→C1/C2）：快照 + 本金口径 → 升值/年化 → 目标进度与偏离检测（双阈值）→ 触发信号 → 回调方向引导 → 人决策、场外执行 → 下一快照自然反映。**系统不碰执行。**

**F3 市场→建议→审阅→采纳→复盘**（将来闭环 | C3→C4→C1/C2）：可信数据源（数字）+ AI 检索（叙事）→ 对准目标的建议（带引用）→ 校验门 → 人审批 → 采纳记录 → 到期复盘（重放信息集 + 达成度归因）→ 反哺提案 → 回到人裁决。

**F4 家庭归集**（扩展 | D）：成员标注 → 共用资产归属裁决 → 成员/家庭两级视图 → 家庭盘点报表。

## 5. 业务规则与不变量（全局，约束 A~D）

1. 机器产出（OCR/AI/校验/规则）未经人裁决绝不写入。
2. 快照一旦记录不可改写；更正 = 追加 + 审计痕迹。
3. 凭证永久留存，即使对应记录被更正。
4. 建议绝不直接入账；建议库与账本结构性隔离，采纳只产生「人的决策记录」。
5. LLM 不做算术；进入计算的数字必须来自可信结构化数据源。
6. **目标由人设定**：系统只做对齐分析、偏离提示与复盘对照，绝不代替人设定或修改目标。
7. 升级不降级：能力演进不得丢失历史数据与追溯链。
8. 全程审计：任何写入/更正/采纳/驳回可回答「谁、何时、依据什么」。

## 6. 角色与干系人（同前稿）

本人（Owner）＝唯一决策者与目标设定者；家庭成员＝数据主体与视图消费者，不操作；识别引擎/AI 校验/AI 建议者（机器）＝**信号源**，无写入权、无执行权；校验门（确定性程序）＝守门员，不代替人批准。

## 7. 边界与非目标（同前稿）

- 记账软件式功能（日常收支流水、消费明细分析、预算编制；支出模块只读遗留）
- 交易执行/下单/机构直连写操作
- 多租户 SaaS、账号体系、成员权限隔离
- 无人工确认的全自动记账/自动落库
- 实时行情追踪
- 税务/法律专业结论

## 9. 拍板决定（冻结，10 项）

以下 10 项已于 2026-09-27 按推荐默认冻结：

1. **本金口径**：资产项级「累计投入本金」（外部投入−撤出，不含内生收益），作为快照伴生裁决值登记，不重建历史流水。
2. **目标形态**：两者兼有，以「目标金额 + 期限」为主锚，派生「所需年化收益率」作对齐锚点。
3. **配置框架 + 风险预算**：一次只激活一套（切换留史，非激活可作只读影子视图）；风险预算分期，账本满一年且本金口径稳定后再评估。
4. **复盘 + 执行追踪**：季度固定为主、建议到期为辅；采纳建议只记轻量执行情况（已执行/未执行/部分 + 一句原因）。
5. **可信数据源**：本人维护白名单，非白名单引用自动降级为「叙事参考」，不得进入计算。
6. **家庭口径**：设「家庭池」虚拟成员（不做比例拆分）；视图暂仅本人可见，成员维度以只读汇总报表线下共享。
> 注：家庭池设立/解散/成员进出的生命周期规则，于家庭盘点阶段启动前补充。
7. **同标的多渠道身份**：分渠道多条资产项，视图层以「标的标签」聚合。
8. **合并/拆分/改版**：旧项归档＋新项创建＋血缘链接，历史只追加。
9. **内部买卖登记形态**：轻量「转移事件」（两资产项关联＋本金移动），不做流水。
10. **资产项改名**：显示名与身份解耦，改名留史，校正规则兼容来源旧名。
