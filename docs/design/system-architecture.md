## 1. 域→模块映射与分层

**部署形态**：单一自托管应用（一个后端进程 + 一个前端 + 一个 SQLite 文件 + 一个凭证目录）。模块化单体（modular monolith）：上下文以模块目录与导入边界表达，不拆服务。

**上下文/模块映射**（12 子域 → 7 模块 + 1 横切）：

| 模块 | 承载子域 | 核心/支撑/通用 | 生命周期段（SDP 回溯） |
|---|---|---|---|
| `ledger` 账本 | A1（快照、身份、属性、更正、关系对象） | **核心** | 过去（权威事实） |
| `ingest` 采集录入 | A2（识别、校正、待录入裁决） | **核心**（P1 差异化） | 过去（写入通道） |
| `evidence` 凭证审计 | A3（存证、批次、对账、审计日志） | **核心**（可信底座） | 过去（追溯链） |
| `valuation` 度量视图 | B1/B2/B3/B4（净值、升值、占比、预警） | **核心**（B2 本金口径为 P2 差异化；B1/B3/B4 支撑） | 现在 |
| `planning` 目标配置 | C1/C2（目标版本、配置框架、偏离引擎） | 支撑 | 将来 |
| `advisor` 建议复盘 | C3/C4（建议状态机、校验门、复盘） | **核心**（使命③差异化；LLM 接入部分为通用） | 将来（闭环回看过去） |
| `platform` 横切 | 识别引擎适配、LLM 供应商、迁移、备份、任务执行器 | 通用 | 豁免：无业务语义，承载全局不变量的机械部分（SDP-3 豁免理由） |

**主域 D（家庭盘点）不设独立模块**：共有归属是 `ledger` 内的关系对象（资产项↔成员/家庭池），家庭视图是 `valuation` 的归集维度。豁免理由：业务架构已定性 D 为「聚合上的标注与归集视角，不改变聚合边界」——仍完全回溯到资产项生命周期。

**分层**（每模块内部同构）：接口层（API 路由，冻结契约）→ 应用层（用例编排、事务边界、幂等）→ 领域层（聚合、不变量、纯计算：净值/升值/偏离/TWR-XIRR，零 I/O）→ 基础设施层（SQLite、文件存证、OCR/VLM/LLM 适配）。

**模块依赖方向**（无环，箭头=依赖）：

```
ingest ──写端口──▶ ledger ◀──只读── valuation ◀──只读── planning ◀──只读(数字)── advisor
ingest/ledger ──引用──▶ evidence        advisor ──▶ platform(LLM)   所有模块 ──▶ platform(存储/审计)
```

关键规则：①`ledger` 是唯一持有账本写端口的模块；②`advisor` **不存在**指向 `ledger` 写端口的依赖（结构性隔离，见 §5）；③`ingest` 会话态自持，采纳时经 `ledger` 写端口落账；④`evidence` 被引用而不引用他人。

**与生命周期三段对应**：过去 = ledger + evidence + ingest（写入侧）；现在 = valuation（读侧）；将来 = planning + advisor。F1 落在「过去」，F2 跨「现在→将来」，F3 在「将来」闭环，F4 是「现在」的成员维度投影——四条流程均可沿模块图走通，满足 SDP-3。

## 2. 领域模型与聚合契约

**资产项（聚合根，`ledger`）**：
- 身份：持久代理 ID；显示名与身份解耦（拍板 10），改名 = 追加显示名历史；机构渠道为身份构成（拍板 7：同标的多渠道 = 多条资产项）；标的标签 = 属性树新 type（`instrument`），跨渠道聚合仅在视图层按该属性分组。（2026-11-04 修订：ADR-0019 已取代「属性树 + type 枚举」路线——类别走 `asset_classes` 树，机构/渠道/成员/标签走 `institutions`/`channels`/`members`/`tags` 平坦字典表，单值维度列化到 `asset_items`；标的标签落为 `tags`，跨渠道聚合仍在视图层。）
- 聚合内一致性边界：资产记录追加、本金口径变更、清零/归档、共有归属变更，均以资产项为根在同一事务内校验不变量。
- 状态机：创建 → 活跃 → 清零归档（只追加不删史，拍板 8）。

**资产记录（快照，write-once）**：`(资产项, 快照日期)` 唯一；金额非负（0=该日余额为零，ADR-0015）+ 资产/负债侧；携带凭证/批次引用或人工标注（R-10）；预留 `cost_basis / units / nav` 扩展字段位（追加式、可空）。更正 = 追加 + 审计（不变量 2）。

**本金口径（B2 写事实落 `ledger`，计算落 `valuation`）**：口径变更史为权威（每次变更 = 人裁决值 + 理由/凭证 + 生效日期，R-9）；每条快照行冗余携带**写入时生效**的 `cost_basis`（write-once，读时免 join）。升值 = 市值 − 口径；TWR/XIRR 以口径变更为「标记过的外部现金流」输入（业界参考 §2 契约），不依赖流水。

**关系对象**（业务架构 §3 增补三件套）：
- **转移事件**：独立小聚合，关联两资产项 + 金额 + 日期 + 本金移动方向 + 裁决标注。不变量：两侧本金移动等额（净值不变）；不产生流水明细（拍板 9）。
- **血缘链接**：独立 append-only 对象：旧项→新项 + 类型（改名/合并/拆分/改版）+ 拆分比例（可空）。创建即固定。
- **共有归属**：资产项聚合内属性（当前值 + 变更留史）；家庭池为虚拟成员（拍板 6）。

**目标聚合（版本化，`planning`）**：目标（根）= 目标金额 + 期限为主锚，派生所需年化（计算值）；每次变更 = 新 GoalVersion + 理由，状态：草案→生效→被取代（拍板 2）。配置框架实例（60/40、全天候、glide path…）一次只激活一套，切换留史；目标占比向量引用属性维度 + 目标版本，glide path 以分段线性 `w(t)` 表达；再平衡参数 = Vanguard 三元组（frequency + 双阈值[绝对/相对取先触发] + destination）。

**建议与复盘（`advisor`，与账本隔离的表族）**：
- 建议聚合：状态机 `生成→门校验(通过/失败)→待审→采纳/驳回→执行追踪(已/部分/未+一句原因)→过期归档`（拍板 4）；随附**信息集快照**（建议时点可信数字的 write-once 冻结）、引用列表（来源+时点+白名单标记，非白名单降级「叙事参考」，拍板 5）、门裁决与人裁决记录、模型与 prompt 版本。
- 复盘聚合：发起（季度固定/建议到期）→ 关联建议批 + 目标版本 → 归因四分类 → 结论 → 反哺提案（只出建议，人裁决）。

**不变量→模型落位**：①机器产出不过人不写入 → `ingest` 采纳用例是唯一通道；②快照不可改写 → 存储层 write-once + `ledger` 聚合拒绝 update；③凭证永久留存 → `evidence` 独立生命周期，无删除端口；④建议不入账 → `advisor` 无账本写端口（结构保证）；⑤LLM 不做算术 → 校验门重算 + 领域层纯函数计算；⑥目标由人设定 → GoalVersion 只能由人触发用例创建；⑦升级不降级 → 迁移策略 §4；⑧全程审计 → `evidence` 审计日志覆盖全部写路径。

**type-fields/attrs 方向**：维持「统一属性树（type 区分维度）+ N:M 挂接」（沿 ADR-0001 方向），不为维度建专用实体表；扩展 = 增加 type 枚举（如 `instrument` 标的标签），不动模型骨架。（2026-11-04 修订：该路线已由 **ADR-0019** 取代——改为 5 张专用字典表（`asset_classes` 树 + `institutions`/`channels`/`members`/`tags` 四张平坦字典）并把这些维度**列化**进 `asset_items`，`attributes`/`asset_attributes` 已删除；「加 type 枚举」的扩展方式不再存在。）

## 3. 关键数据流与时序

**F1 录入管线**（过去 | ingest→ledger→evidence）：
上传截图 → **立即存证**（原图 + SHA256，write-once，先于任何识别）→ 识别（OCR/VLM，慢）→ 识别清单 → 校正规则应用（parse 后、preview 前，沿 ADR-0004 缝位）→ 可选 AI 一致性校验（慢，信号不改数）→ 待录入清单（人逐行裁决：更新/新增/清零）→ **采纳 = 单事务**（写快照 + 伴生本金口径 + 挂凭证链 + 写审计）→ 对账锚点比对，差异高亮供人处置。关卡：写入前必须过人（不变量 1）。

**F2 升值→目标→再平衡**（现在→将来 | valuation→planning）：
快照落账（F1 触发）→ valuation 读时计算净值/升值/双口径收益 → 偏离检测（触发源：新快照落账、定期巡检、手动刷新）→ 双阈值取先触发 → 预警信号 + 回调方向引导 → 人决策、场外执行 → 下一快照自然反映。全同步读路径，无慢步骤，系统不碰执行。

**F3 建议闭环**（将来 | advisor）：
触发（手动/定时）→ **冻结信息集**（可信数据源数字快照，write-once）→ LLM 生成（异步任务，带引用）→ 确定性校验门（算术重算、引用可解析、与账本现状一致）→ 门失败 = 状态机终态，**账本侧不可达**；门通过 → 待审（持久化中断：任务与状态落库，重启可续，拒绝/超时落终态，不留僵尸）→ 人采纳/驳回 → 采纳产生「人的决策记录」；若涉及实际操作，由人另行触发 F1/口径变更用例（独立事务，非 advisor 路径）→ 到期复盘（重放信息集 vs 实际走势 + 未采纳反事实）→ 归因 → 反哺提案 → 人裁决 → 目标/配置/阈值出新版本。

**F4 家庭归集**（扩展 | ledger→valuation）：成员标注（共有归属）→ 共用资产归属裁决 → 成员/家庭池两级聚合视图 → 盘点报表。纯读路径。

**同步/异步边界与慢管线策略**：唯一慢源 = OCR/VLM/LLM 三类外部调用。统一策略：DB 落库任务表 + 进程内后台执行器（不引入外部队列/broker）+ 幂等结果写入 + 前端进度轮询；失败一律**降级不阻塞**（校验失败→「未校验」；生成失败→状态机终态）；重试有上限。快步骤（存证、规则应用、清单计算、采纳事务）保持请求-响应同步。

## 4. 存储与演进

- **形态**：单 SQLite 文件（WAL）+ 文件系统凭证目录。数据世代 = 主版本（升级自动迁移、不支持降级）。
- **分区（同库内表族隔离，写端口按模块隔离）**：
  - 账本区（append-only/write-once）：快照、口径变更史、转移事件、血缘链接、归属史、审计日志；
  - 参考区（可变，变更留史）：属性树、目标版本、配置框架、来源组、校正规则、LLM 供应商；（2026-11-04 修订：ADR-0019 已把这里的「属性树」换为 5 张专用字典表——`asset_classes`（树）/`institutions`/`channels`/`members`/`tags`。）
  - 建议隔离区：建议、信息集、引用、复盘——与账本区无外键指向写路径，仅只读引用账本 ID；
  - 会话/任务区（可弃但落库以支持续跑）：识别清单、比对结论、任务状态；
  - 凭证文件：原图 + 哈希，按批次组织，文件不可变，独立于记录生命周期（R-11）。
- **迁移策略（已冻结）**：采用**手写幂等编号迁移脚本 + `schema_version` 表**，启动时顺序执行。理由：单库单方言，迁移框架的核心价值（多方言、autogenerate）用不上且引入依赖；手写脚本可逐条评审，与「模型变更走 ADR、演进有据」直接对齐；幂等 + 迁移前自动备份兜底。
- **备份恢复**：一致性文件级备份 = SQLite 在线备份 API（或 WAL checkpoint 后拷贝）+ 凭证目录，两者必须同备份（否则追溯链断）；恢复 = 文件替换 + 世代校验；保留最近 N 份，手动/脚本触发。
- **金额约定**：非负 + 字符串序列化 Decimal + side 字段（沿 ADR-0002 方向、ADR-0015 修订值域，扩展至全部新表）；比率/收益率为派生计算值，不落权威存储。

## 5. 信任架构

- **AI 不可达账本（结构性隔离，非约定）**：`advisor` 模块在依赖图上不存在 `ledger` 写端口的导入路径；以导入边界检查 + 测试锁定「违规路径不可达」（业界参考 §3：gate fail 边不可达并有测试）。建议采纳后的任何落账都是**人触发的独立用例**，走 F1 同一写端口（须附凭证或原因标注）。
- **审计链**：append-only 审计日志覆盖全部写路径（采纳、更正、口径变更、转移、血缘、目标版本、建议裁决、规则变更），条目 = 谁/何时/何操作/前值后值/来源凭证引用；hash-chain（prev_hash 链接）分期引入：三期、建议闭环上线前（拍板决定 2）。
- **引用校验**：建议每条断言附引用（来源+时点）；门做机器校验——可信数据源引用必须在信息集内存在且数字一致；白名单外自动降级「叙事参考」，不得进入计算（拍板 5）。
- **LLM 边界**：进入计算的数字一律来自可信结构化数据源并由确定性代码重算（偏离、收益、建议内数字）；LLM 只做叙述与假设生成；OCR/VLM 同为信号源。信息集冻结保证「建议时点」可重放，模型与 prompt 版本入审计。
- **校验门位置**：两道性质不同的门——F1 的门是**人**（待录入清单逐行裁决，AI 一致性校验只是信号）；F3 的门是**确定性程序 + 人**两层（生成后、人审前）。校验门是 `advisor` 内的独立纯函数组件，不共享 LLM 客户端。

## 6. API 与契约风格

- **风格**：资源导向 REST；状态机动作用显式动作端点（如建议的 `approve/reject`）；单客户端不做 URL 版本化，破坏性变更随数据世代走。契约以 spec 文件**冻结后**前后端并行开发（沿既有工作流：冻结契约→后端→前端→`tsc --noEmit` 验证）。
- **错误契约**：统一错误信封 `{error: {code, message, details}}`；HTTP 语义 + 业务错误码枚举；校验错误按字段定位。
- **幂等键**：一切写操作支持客户端幂等键（请求 ID 去重）；天然幂等优先——快照 `(资产项, 快照日期)` 唯一，冲突显式返回而非静默覆盖；转移事件、采纳事务、模板生成均带唯一约束（先例：`(template_id, period)`）。
- **读路径契约要点**：视图响应必须携带**口径元数据**——快照日、口径版本、降级标注（「率不可得」「缺数据 carry-forward」显式标注，业界参考 §2/§4 教训：缺数据路径必须显式设计，杜绝 `undefined` 传染）。
- **关键契约形状**（举例非罗列）：资产记录行（side/金额字符串/凭证引用/cost_basis 位）；待录入清单行（项目名/来源金额/映射目标/动作/差异/校验标注）；建议对象（状态/引用/信息集引用/门结论/裁决记录）；目标版本（金额/期限/派生年化/理由/框架引用）；审计条目。

## 7. 演进路线（按使命分期，每期最小闭环）

| 期 | 使命锚点 | 模块范围 | 最小闭环 |
|---|---|---|---|
| 一期 个人账本 | 「认清现状」 | ledger + evidence + ingest + valuation(B1) + 审计从第一天贯穿 | 截图/手工录入 → 存证 → 人裁决采纳 → 净资产曲线可看、可追溯 |
| 二期 升值 | P2 | 本金口径 + 转移事件 + 血缘/改名 + 双口径收益(B2) | 口径裁决 → 升值额/率、TWR/XIRR 可信呈现 |
| 三期 目标与建议 | 使命②③ | planning(C1/C2 偏离+引导) → advisor(C3/C4) + B4 预警 | 目标版本 → 偏离信号 → 建议 → 门 → 人审采纳 → 到期复盘归因 → 反哺 |
| 四期 家庭 | 使命① | 共有归属补全 + 家庭池 + 两级视图(D) | 成员标注 → 家庭盘点报表 |

每期先走骨架（端到端一条垂直切片）再加宽；风险预算类指标按拍板 3 延后（账本满一年且口径稳定后评估）。

## 8. ADR 候选清单 + 非目标与风险

**ADR 候选（各一句话）**：
1. 模块化单体：上下文以模块目录 + 导入边界表达，依赖无环，隔离由测试锁定。
2. 手写幂等编号迁移 + `schema_version` 表，不引入迁移框架。
3. 金额一律非负字符串 Decimal + side 字段（0=该日余额为零，ADR-0015），扩展至全部新表（追认并推广 ADR-0002）。
4. 慢管线 = DB 任务表 + 进程内后台执行器，不引入外部队列。
5. 审计日志 append-only 起步，hash-chain 分期引入（时点已冻结：三期、闭环上线前）。
6. 建议库与账本同库表族隔离 + 写端口不可达，采纳走人触发的账本写端口。
7. 本金口径以变更史为权威，快照行冗余携带生效 `cost_basis`（write-once）。
8. 标的标签 = 属性树新 type `instrument`，跨渠道聚合仅在视图层。（2026-11-04 修订：ADR-0019 已取消「属性树新 type」路线，标的标签落为 `tags` 字典表 + `asset_item_tags` 关联表；跨渠道聚合仍在视图层。）
9. 信息集冻结 = write-once 结构化快照，模型/prompt 版本随审计记录。
10. 读时计算优先（数据量千级行），不做物化视图，预留缓存缝。

**架构层非目标**：多用户/权限体系、实时行情、微服务、外部消息中间件、事件溯源（审计日志≠ES）、URL API 版本化、完整 C4 四层文档。

**主要风险**：①SQLite 写并发（慢任务 + 请求交叠）→ WAL + 短事务 + 单写者约定，单用户可接受；②识别管线复杂度向账本蔓延 → 会话区隔离，ingest 仅经写端口触 ledger；③LLM 供应商/模型漂移影响建议可比性 → 版本入审计；④手写迁移质量依赖评审 → 幂等 + 迁移前自动备份；⑤glide path 时间演进使偏离计算复杂 → 分段线性 + 「当期目标」取值函数单独测试；⑥凭证文件与 DB 分离丢失 → 统一备份程序强约束。

**段规（新功能评审先问：进哪段、守不守段规）**

1. 采集：只收三类入账口（快照/裁决登记/参考设定）；写入前必须过人。
2. 处理：读时计算不物化；写路径单事务、更正不改史。
3. 存储：append-only/write-once；迁移走 ADR；凭证与库同备份。
4. 分析：定义在码、判据在库、值在读；灯永不脱离口径。
5. 监控：阈值人设（系统只提案）；口径降级不判绿。
6. 输出：只读投影——导出/备份/投递不得改账。
7. AI：LLM 只在解释/叙述/信号层；数字确定性重算；建议不入账。

**借镜照出的缺口（候选，按使命非目标裁剪）**：⑥ 推式投递；⑤ 主动通知；⑦ 对话式分析（已在路线图）；② 写入后巡检。

| # | 事项 | 决定（已冻结） | 一句理由 |
|---|---|---|---|

## 对业务架构 v1.0 的反馈（架构层暴露的业务缺口）

> **处理记**：6 条反馈中 5 条已并入业务架构 v1.1（R-36/R-37 及三处加注），1 条（家庭池生命周期）记为后续事项，四期启动前补充。

1. **口径变更的时间语义未定义**（R-6/R-9）：口径变更是否带生效日期、历史期升值展示用当时口径还是现口径——直接影响上表拍板项 6，建议业务层补一句。
2. **清零/归档语义不完整**：资产项清零后是否继续采集零值快照、「归档」终态项是否仍出现在视图与复盘范围，F1 有清零动作但生命周期终点未定义。
3. **转移事件与快照的对齐规则缺失**（R-34）：转移登记日是否必须落在快照日、对方资产项是否需同步补录快照，否则两侧本金移动与市值可能瞬时不自洽。
4. **对账触发时机未定**（R-12）：F1 采纳后立即比对，还是独立对账会话？架构暂按「F1 尾部即时 + 可独立重查」双落位，需业务确认。
5. **采纳建议与实际落账的关联缺失**（拍板 4）：执行追踪是否与其后 F1 录入/口径变更建立松散链接（供复盘「执行走样」归因取证），业务架构只说轻量记录、未提与账本的关联形态。
6. **家庭池无生命周期定义**（拍板 6，低优先级）：家庭池作为虚拟成员，其设立/解散/成员进出规则未写，四期前需补。
